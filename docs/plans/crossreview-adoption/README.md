# Контракт: кросс-ревью — контрактные дельты в гейты ревью

## Goal

Перенести в гейты ревью онтошипа три контрактные дельты, выявленные сверкой с
методологией кросс-ревью (репозиторий `EvilFreelancer/crossreview`, изучен
2026-10-04): замысел диффа доступен ревью-осям наравне с конфирмером; отказ
проверки не выдаётся за опровержение находки; инварианты слепого ревью записаны
в KB и переживают будущие правки воркфлоу.

## Done

- Оси `/code-review` знают замысел диффа (intent) — закрыта асимметрия
  «конфирмер знает тикет, оси нет»; ревью без замысла честно называется
  ревью самосогласованности.
- Confirm-ран различает три исхода находки: verified / unconfirmed (проверено —
  не воспроизводится) / unverified (проверка не состоялась: отказ конфирмера);
  отказ API больше не создаёт оператору ложное «нужны глаза человека».
- Инварианты слепого ревью записаны в `docs/reference/` со ссылками на
  воркфлоу-механизмы и линкуются из индекса reference.

## Scope

- `skills/code-review/` — workflow (args.intent в промпты осей) и SKILL.md.
- `skills/ship/` — confirm.workflow.ts (третий статус, retry) и текст шага 6
  SKILL.md о вердиктах гейта.
- `docs/reference/` — новый док инвариантов + строка в его README.
- `docs/plans/README.md` — порядок выполнения планов.

Вне scope: машинерия crossreview (ростеры, trust-флоу, quorum, CLI-детект),
VERDICT-строки, второй раунд ревью дельта-диффа фиксов (отложено сознательно).

## Constraints

- **Слепота ревьюеров не нарушается**: intent — факт оркестратора о замысле
  изменения, не чужой ответ; никаких пересказов находок между ранами.
- Общая форма находки гейта (`{where, claim, evidence, severity, quote?, axis?}`)
  не меняется: confirm-ран принимает находки обоих review-ранов как раньше.
- Retry конфирмера — один, без снифинга причины отказа (причина в тексте
  ошибки приходит отдельным тикетом queue-2/17); второй отказ → unverified.
- Каждый тикет идёт полным лупом `/ship` со своим релизным циклом.

## Context

Источник — заметка оператора о кросс-ревью и репозиторий
`EvilFreelancer/crossreview` (SKILL.md 2.0.0 + references/brief.md), изучены
2026-10-04. Сверка чтением наших воркфлоу показала: **методологическое ядро уже
реализовано нативно** (слепой параллельный fan-out осей/ревьюеров/челленджеров;
подтверждение каждой находки свежей моделью по дословной цитате — сильнее, чем
самопроверка оркестратора; честные счётчики отказов и пропусков; защита от
инъекций через дифф). Решение оператора 2026-10-04: машинерию не брать, взять
три дельты. Проверенные факты, на которых стоят тикеты:

- `reviewer.workflow.ts` передаёт тикет каждому ревьюеру ship-гейта, а
  `code-review.workflow.ts` (filePrompt) intent осям не передаёт — при том что
  confirm-ран args.ticket получает (SKILL.md code-review, шаг 3): ревьюер слеп
  к замыслу, проверяющий — нет. У crossreview это сформулировано как правило
  brief'а: без замысла ревьюер проверяет самосогласованность, а не то, что
  просили.
- `confirm.workflow.ts` (catch в фазе подтверждения) превращает отказ
  конфирмера в `holds: false` → статус unconfirmed → «нужны глаза человека».
  Один сетевой сбой/429 конвертируется в ложный шум оператору. У crossreview
  отказ ревьюера и его ответ — разные исходы (passing-причина → retry, отказ →
  честный отчёт «не ответил»).
- Практика слепого ревью живёт в комментариях воркфлоу и не записана как
  инвариант — одна будущая правка может незаметно её сломать.

Отступление от дисциплины (прецедент — голова queue-2): план-контракт написан
вручную по прямому указанию оператора, без гриллинга — решения приняты в сессии
анализа методологии 2026-10-04; тикеты — штатным прогоном `/to-tickets`.
Порядок: после закрытия queue-2 — его тикеты 15–17 правят те же воркфлоу
(redact, untracked, abort-диагностика), один churn на релизный цикл.
