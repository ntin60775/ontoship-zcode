# Контракт: хэндофф — единый катящийся слепок состояния

## Goal

Хэндофф становится единым файлом `.scratch/handoff-current.md` — полным слепком
последнего состояния работы над проектом, который перезаписывается целиком
(регенерат, не журнал) при каждом закрытии тикета автоматически и при ручном
`/handoff`, и анонсируется SessionStart-хуком без 7-дневного TTL. Класс
коллизий имён `handoff-<sess-id>.md` исчезает по построению.

## Done

- Новая сессия получает по анонсу хука один файл — актуальный слепок состояния
  проекта, независимо от того, чем закончилась прошлая смена: `/handoff` или
  закрытием тикета.
- Файл старше 7 дней не «протухает» для анонса: старый слепок означает, что
  работ не было, — анонсировать его тем более надо.
- Устаревшие `handoff-sess_*.md` зачищены; механика коллизий (timestamp-fallback,
  «никогда не перезаписывать») упразднена за ненадобностью.
- Границы прежние: `.scratch` эфемерен, хэндофф не KB-док, память не
  замещается — файл держит позицию в порядке планов и ссылки, не дублируя
  факты, живущие в репо и памяти.

## Scope

- `skills/handoff/` — SKILL.md: регенерат единого файла; упрощение (без
  sess-id в имени, без ветвей коллизий и timestamp-fallback); шаблон со
  штампами `updated:`/`From:` как provenance.
- `skills/ship/` — SKILL.md шаг 9: автозапись слепка после архивации тикета.
- `hooks/session-start.sh` — анонс `handoff-current.md` по явному имени без
  TTL, миграционный фолбэк на legacy-глоб.
- `docs/plans/README.md` — порядок выполнения планов.

Вне scope: SessionEnd-события хоста, перенос слепка в KB, замена авто-памяти,
смена смысловых секций шаблона (Task/Done/Decisions/Open/Next) — только
provenance-штампы.

## Constraints

- **Регенерат целиком** при каждой записи — никогда не дописка; каждая запись
  переписывает файл полностью.
- **Клей, не вторая память**: позиция в порядке планов, ссылки на коммиты,
  план и ключи памяти; дублировать факты из репо и памяти запрещено.
- `.scratch` остаётся эфемерным (gitignore); хэндофф никогда не становится
  KB-доком.
- Тикеты 01–02 идут полным лупом `/ship` со своим релизным циклом (вендор
  через self-update); тикет 03 — опс-тикет без кода: без гейта и релиза
  (прецедент queue-2/11), верификация — живой анонс хука.

## Context

Решение оператора 2026-10-06 после реальной коллизии: хост выдал новой сессии
неуникальный sess-id (маркер `.session-id` честно перезаписан хуком тем же id,
что у хэндоффа утренней сессии), имя `handoff-<id>.md` оказалось занято, а
скилл ветви для этого случая не имеет — timestamp-fallback сделан
improvisацией. Ожидание оператора, зафиксированное словами: «хэндофф —
единственный файл, в котором всегда слепок последнего состояния работы над
проектом; он должен автоматически обновляться при закрытии тикета».

Механика сегодня (проверено по `hooks/session-start.sh`): хук при старте
пишет маркер из `ZCODE_SESSION_ID` (валидация формата) и анонсирует новейший
`handoff-*.md` по mtime при возрасте < 7 дней (604800 с), никогда не удаляет;
чистку старше 7 дней делает только `/handoff` (`mmin +10080`); глоб
`handoff-*.md` не матчит имя `handoff-current.md` — хуку нужно явное имя.

Альтернативы отвергнуты: пачка файлов с автозаписью на закрытии (накопление и
коллизии возвращаются, выигрывает только момент записи); отказ от хэндоффа в
пользу памяти/KB (память по контракту не таск-стейт, KB — курируемая);
автозапись по SessionEnd-событию хоста (недетерминированно: краш = события
нет, тогда как закрытие тикета — проектная точка).
