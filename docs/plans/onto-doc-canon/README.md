## Goal

Вернуть `/onto-doc` семантику апстрима: пустой вызов = прогон по всему
репозиторию без вопросов оператору, аргумент = опциональная scope-подсказка,
бутстрап и пересборка/починка собранной KB — один и тот же прогон (состояние
KB решает само). Субагенты прогона всегда работают на текущей модели чата —
решение оператора, зафиксированное в констрейнтах.

## Done

- `skills/onto-doc/SKILL.md` переписан под контракт апстрима: нет «If empty,
  ask for the task» и церемонии выбора root/режима — root по умолчанию
  текущий репо (worktree — рекомендация для живого репо: хвост прогона
  безусловно регенерирует реестр `docs/plans/README.md`, незакоммиченные
  правки в живом репо без worktree теряются), режим авто (есть `plan` →
  исполнение, нет → survey), пустой аргумент = весь репо молча, непустой =
  scope-подсказка (данные для surveyor'а). В тексте — фраза о модели с
  причиной и границей: «решение оператора 2026-10-12: стоимость кураторов
  управляется моделью чата на ручном запуске; subagent_model не передавать и
  роль для кураторов не заводить — в отличие от гейтовых ship/grilling;
  пересмотр — только явным запросом оператора». Живая проба: `/onto-doc`
  без аргументов в новой сессии стартует прогон, не задавая вопросов.
- Хедер воркфлоу: `task: required: false` и `root: required: false`
  (наблюдаемы в `:4-11`); abort-текст «Нужен непустой args.task» в файле
  отсутствует; дефолт «весь репозиторий» стоит на входе переменной task
  (`:69`) и покрывает оба живых ключа — пропущенный и пустую строку. Проба:
  CreateWorkflow на tmp-фикстуре (канон onto-doc-parity) с args без ключей
  task и root принимается хостом, прогон зелёный.
- `pytest` зелёный; `lint --strict` зелёный после inventory-синка реестра
  планов.

## Constraints

- `stop-before-commit` (дефолт).
- Семантика прогона (survey → fan-out → lint-гейт → healer ≤ 4 → хвост) не
  меняется.
- Модель прогона — текущая модель чата: `subagent_model` при запуске не
  передаётся, отдельную роль/модель для кураторов не заводить (решение
  оператора 2026-10-12 — отвергло подготовленный в этой же сессии вариант с
  ролью `curator` в трёхслойной системе ролей).
- Граница с onto-doc-hygiene: canon не заходит в hygiene-области (перечень
  в Scope); порядок шипов — решение оператора в «Порядке выполнения»,
  рекомендация hygiene → canon: якоря canon лежат выше hygiene-правок и не
  сдвинутся, обратный порядок сдвигает hygiene-якоря на 5 строк.
- Мораторий инвариантов: новых инвариантов и реестров не заводить.

## Context

- Первоисточник — клон апстрима ontoship-omp, `.omp/commands/onto-doc.md`:
  `args: "[scope] (empty → whole repo)"`; survey с замером покрытия
  (`gitmark stat`), декомпозиция на зоны, кураторы с правилом «search first,
  never duplicate — edit existing docs», шаг 5 — линт с починкой. Бутстрап и
  пересборка — один прогон; содержание KB берётся из кода, а не из слов
  оператора, аргумент только сужает охват.
- Поломка (вердикт оператора 2026-10-12): движок queue-2/05 унаследовал
  жёсткое требование `args.task` (ассерт `:86-88`, текст льётся в промпты
  `:226`, `:323`); восстановление команды в v0.5.47 (onto-doc-command)
  переписало в скилл контракт движка вместо контракта апстрима —
  самодостаточная команда стала командой-допросом, сверху добавилась
  церемония выбора root/режима.
- Грилл 2026-10-12: challenger-ран `dwfrun-8e44670e` — 7 решений, 5
  substantial (все сведены находкой хедера) / 2 minor, 0 упавших. Сквозная
  находка: хедер объявлял `task`/`root` `required: true`, а хост валидирует
  args по хедеру до старта тела и отбивает missing required на сабмите
  (contour, урок 10, `.zcode/skills/contour/SKILL.md:144-160`) — дефолт
  «только в теле» был бы мёртвым кодом, дифф «только :86-88» не реализовал
  собственную цель. Пере-решения: required-флаги в дифф включены, пункт
  про `workflow-args.md` выброшен (task там не упомянут — evidence d6 было
  ложным), фраза о модели в SKILL несёт причину и триггер, а не одну
  механику.
- Модель: модель рана задаётся на запуске через `subagent_model`
  CreateWorkflow (facade dynamic-workflows §16.1), per-subagent выбора
  внутри рана нет (§2: «there is no per-subagent tool profile or model
  choice») — «модель чата» и есть модель всех субагентов прогона (surveyor,
  кураторы, healer). Оператор 2026-10-12 выбрал так: без отдельной роли,
  стоимость управляется выбором модели чата на момент ручного запуска.
  Условность: если хост даст дешёвый каталог моделей или базовый вес
  субагента не влезет в окно модели сессии (ContextLimit у surveyor'а) —
  единственный рычаг «модель чата» окажется недостаточным, тогда
  срабатывает триггер: явный запрос оператора на модель кураторов,
  отличную от модели чата. Подготовленный в той же сессии вариант с ролью
  `curator` (fail-closed потребление по паттерну ship шаг 6) отвергнут.
- Согласование с onto-doc-hygiene (draft): оба плана правят
  `skills/onto-doc/onto-doc.workflow.ts`, области диффов ортогональны
  (canon — хедер/:69/:84-88; hygiene — redact/промпты/хвост). Порядок —
  решение оператора; рекомендация hygiene → canon (очередь старше,
  verified-находки не протухнут; якоря см. Constraints).
