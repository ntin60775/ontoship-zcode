# 13: Разбивка reviewer-гейта по файлам

**What to build:** шаг 6 лупа /ship (`skills/ship/reviewer.workflow.ts`) переживает
крупный дифф на модели с малым контекстным окном: тот же пер-файловый паттерн,
что зашиплен в тикете 06 для code-review workflow — список файлов через
`git diff --numstat` с потолками → fan-out «файл × ревьюер» → существующие
пер-находочные конфирмеры → неизменный контракт возврата (findings с
verified/unconfirmed), чтобы шаг 6 скилла ship не менялся вовсе.

**Blocked by:** 06 (даёт обкатанный паттерн разбивки; шипится раньше).

**Решение оператора (2026-10-01):** «разбивка всегда» — reviewer-гейт остаётся
последним монолитным читателем диффа; challenger читает компактный JSON
(дробить не нужно), onto-doc разбит по кускам. После 13 вся ревью-машинерия
плагина пер-файловая.

- [ ] `reviewer.workflow.ts` разбит по файлам: numstat с потолками (2000 строк
      диффа/файл, 20 файлов), сверх потолка — честный пропуск с пометкой;
      конфирмеры per-finding без изменений
- [ ] контракт возврата прежний: findings с verified/unconfirmed + conclusion,
      подтверждено прогоном на реальном тикете
- [ ] приёмка: крупный дифф (≥2 тыс. строк) проходит гейт целиком на
      reviewer-роли (qwen-fp8) без ContextLimit
- [ ] мелкий дифф — поведение совместимо со старым (стоп-поинты лупа /ship не
      меняются)
- [ ] `gitmark lint` + `pytest` зелёные
