# 13: Разбивка reviewer-гейта по файлам

**What to build:** шаг 6 лупа /ship (`skills/ship/reviewer.workflow.ts`) переживает
крупный дифф на модели с малым контекстным окном: тот же пер-файловый паттерн,
что зашиплен в тикете 06 для code-review workflow — список файлов через
`git diff --numstat` с потолками → fan-out «файл × ревьюер» → существующие
пер-находочные конфирмеры → неизменный контракт возврата (findings с
verified/unconfirmed), чтобы шаг 6 скилла ship не менялся вовсе.

**Blocked by:** 06 (даёт обкатанный паттерн разбивки; шипится раньше).

**Решение оператора (2026-10-01):** «разбивка всегда» — reviewer-гейт остаётся
последним монолитным читателем диффа; challenger читает компактный JSON
(дробить не нужно), onto-doc разбит по кускам. После 13 вся ревью-машинерия
плагина пер-файловая.

- [x] `reviewer.workflow.ts` разбит по файлам: numstat с потолками (2000 строк
      диффа/файл, 20 файлов), сверх потолка — честный пропуск с пометкой;
      конфирмеры per-finding без изменений
- [x] контракт возврата прежний: findings с verified/unconfirmed + conclusion,
      подтверждено прогоном на реальном тикете
- [x] приёмка: крупный дифф (≥2 тыс. строк) проходит гейт целиком на
      reviewer-роли (qwen-fp8) без ContextLimit
- [x] мелкий дифф — поведение совместимо со старым (стоп-поинты лупа /ship не
      меняются)
- [x] `gitmark lint` + `pytest` зелёные

**Отгружено (2026-10-01).** Коммит `e9964e3` (worktree `ship/queue2-13-reviewer-gate`),
ff-мерж в main, релиз `v0.5.8` (`48e52d8`), пин (`b359c2c`), self-update — вендор
совпал с рабочим деревом, `gitmark version` 0.5.8, реестр синхронен сразу (урок I7
тикета 06 применён: гейт инвентарём до коммита). Приёмка: синтетический дифф
2080 строк (3 файла по 640–800, каждый ниже потолка) дважды прошёл гейт на
qwen-fp8 — 10/10 файл-задач без единого ContextLimit; затем гейт на настоящем
диффе тикета — dogfood (сплит-гейт ревьюит собственную разбивку). Гейты нашли
и закрыли 13 находок: ломающий интеграцию `..`-отлут root (сам добавил по
self-review находке — снят: root доверенный ввод, трейд-офф с противоположной
находкой следующего гейта задокументирован в комментарии), neutralize расширен
на все `<` с lookbehind против double-escape, redact дополнен JSON-стилем
(`"key": "value"`) и суффикс-блэклистом с кавычкой, overflow-файлы именуются,
numstat в try/catch, default base=HEAD возвращён; проверка эвристики — 18
node-кейсов. Два конфирмера на 35b дали сбой «typed ask без submit_result» —
единственный нестабильный паттерн новой роли, изолирован catch'ем (находки
не терялись, ярлык unconfirmed). По ходу рана: роли переведены оператором на
`qwen3.6-35b-a3b$high` (смоук OK; fp8 остановлен как медленный), заведён тикет
14 (вопрос оператора о ролях confirmer/synth). Отклонения: dev-ветки нет — suite
на ветке и на main; подтверждения мержа и деплоя одним сообщением «continue
и деплой».
