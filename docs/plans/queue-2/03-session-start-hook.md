# 03: SessionStart-хук свежести индекса

**What to build:** при старте сессии в проекте с KB плагин сам замечает, что
markdown менялся после последней сборки индекса, и говорит агенту перестроить
индекс (или строит сам) — KB не отвечает устаревшими находками после правок.

**Blocked by:** 01 (хук едет с установленным плагином).

- [x] `hooks/session-start.sh`: сравнение mtime новейшего `.md` в `docs/` против
      `.gitmark/index.db`; плагин не в KB-проекте — тихий выход 0
- [x] `deploy.json` получает mapping `hooks → .zcode/hooks` (раннер вендорит код);
      регистрация хука в `<repo>/.zcode/config.json` — **данные проекта**:
      через post_update `say`/runbook, не раннером
- [x] Перестройка индекса — по выбору: напоминание в stdout хука (агент увидит) или
      тихий `gitmark index` (флаг); по умолчанию — напоминание, не побочный эффект
- [x] Прогон: правка `docs/*.md` → новая сессия видит напоминание; свежий индекс —
      тишина; отсутствие `.gitmark/` — предложение построить

**Отгружено (2026-10-01).** Коммиты `7efa273` (worktree `ship/queue2-03-hook`),
`2053355` (release 0.5.4), `172dcac` (self-update; регистрация хука в
`.zcode/config.json` закоммичена одним коммитом с вендором `.zcode/hooks/` —
находка ревью №2: без этого окна «регистрация в git, кода ещё нет» ловила бы
recoverable-ошибку на каждом старте сессии). Релиз `v0.5.4`, пин `v0.5.4`
(`99075f2`), update обоих потребителей (маркетплейс-репо `4d3ea11`); в обоих
`deploy-check` из вендорного пути зелёный, `gitmark version` = 0.5.4. Ревью
(`GLM-5.3-Flash$max`, воркфлоу reviewer): 7 находок, все независимо подтверждены —
6 исправлено: **охват расширен с `docs/` до корпуса движка** (`git ls-files -c -o
--exclude-standard -- '*.md'`, medium: правки `AGENTS.md`/`SKILL.md` раньше
пропадали незамеченными — цель тикета по букве выполнялась, по смыслу нет);
mtime из будущего пропускается (иначе вечное напоминание, а с `--rebuild` —
молчаливый rebuild на каждом старте); не-git репозиторий = не KB-проект, тишина
(заодно убирает ложные срабатывания на gitignored md, которых нет в индексе
движка); ранбук правдив про рантайм: SessionStart стреляет только на
`startup`/`resume` (после `/compact` — до рестарта сессии тишина, известное
ограничение); `timeoutMs` 60000 в шаблоне + оговорка про большие KB (тихий
rebuild вне таймаута умрет бессловесно; индекс не портится — одна транзакция);
7-я находка — положительное подтверждение безопасности вывода (фиксированные
сообщения, инъекция из имён файлов невозможна, JSON-контракт верен). Отклонения:
MR → локальный dev-меж FF (прецедент 01–02); живой probe срабатывания в новой
сессии не состоялся — headless `zcode.cjs -p` упал в `Model creation failed`
(auth-контекст CLI, флага `--model` нет): схематика вывода и discovery
`.zcode/config.json` доказаны чтением бандла рантайма, сценарии тикета
проверены руками на живом самодеплое (свежий индекс — тишина; устаревший md
включая `AGENTS.md` вне `docs/` — JSON-напоминание; отсутствие `.gitmark/` —
предложение построить; `--rebuild` тих; все пути exit 0), живое срабатывание
покажет первая интерактивная сессия (запись хука — `~/.zcode/v2/logs`; при
первом старте zcode может однократно спросить доверие к project-хуку —
admission-гейт workspace-хуков).
