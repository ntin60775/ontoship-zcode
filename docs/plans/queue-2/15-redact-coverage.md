# 15: Полнота redact — матрица форматов и баланс fp/leak

**What to build:** `redact()` ревью-машинерии закрывает наблюдённые дыры и
перебалансирует ложные срабатывания по утверждённой оператором матрице
форматов. Все находки — verified конфирмерами в ране 14/01 (node-пробы),
унаследованы от baseline 13 и сознательно не чинились после приёмочного
прогона (изменение поведения redact обесценило бы приёмку). Копии redact
самодостаточны по паттерну репо и должны остаться синхронными:
`skills/ship/reviewer.workflow.ts`, `skills/ship/confirm.workflow.ts`,
`skills/code-review/code-review.workflow.ts` (третья — с оглядкой на 14/02,
который переводит code-review на общий confirm-ран).

Наблюдённое (пробы из рана 14/01):

- PEM-регекс `-----BEGIN [A-Z ]*PRIVATE KEY-----` не маскирует
  `-----BEGIN PGP PRIVATE KEY BLOCK-----` (суффикс ` BLOCK` вне паттерна) и
  не-ASCII заголовки; тело ключа доходит до оператора.
- (ран 14/02, node-проба конфирмера) паттерн не матчится и там, где в префиксе
  *до* `PRIVATE KEY` есть символы вне `[A-Z ]` — например цифра
  (`-----BEGIN GO TC36 WMAP PRIVATE KEY-----`: проба NO MATCH, без цифры —
  MATCH, тело ключа утекает); а также CERTIFICATE/X509/TRUSTED
  CERTIFICATE/PUBLIC KEY — сертификаты и публичные ключи публичны по
  назначению, но матрица должна вынести по ним явный вердикт.
- (ран 14/02 v3, node-проба конфирмера) значения короче 4 символов после
  `key=value` не маскируются (`TOKEN=abc` проходит без замены — лимит
  `[^\s"']{4,}`); ограничение задокументировано в шапках копий redact, но
  матрица должна дать по нему явный вердикт (пустое значение секрета не несёт,
  практический риск — ветка 1–3 символов).
- (ран 14/02 v4, verified конфирмером; решение оператора 2026-10-02 —
  follow-up) ответ модельного сводчика уходит на выход без пост-redact:
  markdown-отчёт публикуется артефактом как есть (`reportMd = answer`),
  дайджест ship-гейта — так же с 14/01. Вход сводчика уже редактируется
  (`neutralize(redact(...))`), но обещание шапки «best-effort redacted on
  output» формально шире факта. Матрица: вердикт по пост-redact модельных
  сводов (прямой redact всего отчёта даёт FP на прозе).
- (ран 14/02 v4, verified) redact применяется к natural-language claim
  («bearer authentication» → «bearer [REDACTED]») — унаследовано от
  queue-2/06, не регресс 14/02; матрица даёт вердикт по балансу fp/leak на
  natural-language полях.
- Альтернатива `eyJ[A-Za-z0-9_-]{10,}` маскирует любой base64url-литерал
  без требования контекста секрета: `state=eyJyb290…` → `state=[REDACTED]`,
  JWT в URL маскируется частично.
- Проходят без маскирования: raw hex-ключи без ключевого слова рядом, raw
  base64 без префикса `eyJ`, креды в query-параметрах URL.
- Ложные срабатывания: `auth = "…"`, `token = "…"` с легитимными значениями
  переменных маскируются (категория `auth` широка; exclusion-лист спасает
  только `auth_type/url/provider/…`).

**Blocked by:** None (can start immediately; файлы пересекаются с 14/02
минимально — свериться с его исходом перед правкой третьей копии).

- [ ] матрица форматов утверждена оператором: что маскируем, что нет,
      баланс fp-vs-leak (урок 13: агрессивный паттерн без разделителя
      маскирует обычную прозу)
- [ ] PEM: `PGP PRIVATE KEY BLOCK` и схожие суффиксы маскируются;
      node-пробы
- [ ] `eyJ`/base64url маскируется только при контексте секрета;
      `state=eyJ…` не маскируется; node-пробы
- [ ] query-креды и raw hex/base64 — вердикт с пробами (маскируем или
      задокументированный пропуск в шапке функции)
- [ ] FP на `auth`/`token`-именах — вердикт: расширенный exclusion-лист или
      документированный трейд-офф
- [ ] все копии redact синхронны; единый node-набор кейсов прогнан по всем
- [ ] приёмка: гейт на синтетическом диффе с секретами всех форматов из
      матрицы — вердикты находок читаемы, секреты не доходят до вывода
- [ ] `gitmark lint` + `pytest` зелёные

**Constraints:** `stop-before-commit` (дефолт); best-effort-статус redact
сохраняется (шапка функции честно называет ограничения «не гарантия»);
расширение не должно маскировать легитимную прозу — каждый новый паттерн с
node-пробой на позитиве и негативе.
