# 01: Канал доставки — раннер маркетплейса + самодеплой

**What to build:** плагин ставится в любой проект одной командой раннера
(`deploy/deploy-plugin.py install ontoship <repo>` — скиллы вендорятся в `.zcode/`
по маппингам `deploy.json`), и первый настоящий потребитель — **сам репозиторий
плагина**: он вендорит собственный последний релиз и работает внутри собственного
онтошипа.

**Blocked by:** None (can start immediately). `deploy.json` v1 уже на main
(`7570688`), каталог пинует `v0.5.1`, первый деплой сделан в репо маркетплейса.

- [ ] Runbook `docs/ops/install.md`: install/update/check/remove через раннер;
      релизный цикл (тег в репо плагина → правка пина в `marketplace.json` →
      `update` в проектах); журнал `.zcode/deployed.json` коммитится, бэкапы — нет
- [ ] Самодеплой: `install ontoship` в собственный репо → `.zcode/skills` из
      пин-тега; скиллы видны в воркспейсе репо по слэшу; журнал закоммичен
- [ ] Dev-цикл задокументирован: правки скиллов проверяются pytest+probe, доезжают
      релизным циклом; вендоренная копия = последний релиз, не рабочее дерево
- [ ] `.gitignore`: `.zcode/.backup/` (журнал — коммитится)
- [ ] `.zcode-plugin/plugin.json` снесён: раннер его не читает, глобальная
      установка проектных плагинов запрещена политикой маркетплейса; источник
      версии — `package.json` (остаётся)
- [ ] `version` в `package.json` синхронизирован с релизным тегом (сейчас 0.5.0 при
      пине v0.5.1 — `gitmark version` врёт)
- [ ] Dev-цикл — релизный каданс (решение оператора, 2026-09-30): правки скиллов
      проверяются pytest+probe и доезжают тегом; dev-пина на ветку нет
- [ ] `gitmark lint` + `pytest` зелёные
