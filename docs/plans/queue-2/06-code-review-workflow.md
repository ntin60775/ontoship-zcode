# 06: code-review workflow — две оси параллельно

**What to build:** ревью диффа запускается workflow с двумя независимыми осями
параллельно (корректность и качество/опасные места), на явно назначенных моделях
ролей; свод вердиктов приходит оператору одним читаемым списком с вердиктами
verified/unconfirmed по каждой находке.

**Blocked by:** None (can start immediately).

- [x] workflow-файл существует; обе оси отрабатывают параллельно на реальном
      диффе и сводятся в один отчёт
- [x] вердикты находок различимы (verified / unconfirmed), находки опираются на
      цитаты кода
- [x] `gitmark lint` + `pytest` зелёные

**Решения прогона (2026-10-01).** Разбивка по файлам — **всегда** (решение
оператора): ось получает не весь дифф, а дифф одного файла (`git diff
--numstat` → fan-out ось × файл); потолки — 2000 строк диффа на файл,
20 файлов на прогон, 8 находок на файл-ось; сверх потолка — пропуск с пометкой
в отчёте, не молча. Причина: ContextLimit neuraldeep/qwen3.6-fp8 на целом
диффе (ось осела на ~292 тыс. токенов, вторая в окно не влезла); компакт
рантайма не гарантирует вмещение (документированный предел — «даже после
компакта»). Следствие: контекст агента перестал зависеть от размера диффа —
роли `reviewer`/`challenger` на `qwen3.6-fp8$high` (user-слой, решение
оператора «квен почти бесплатный») жизнеспособны. Контракт для потребителей —
SKILL.md скилла, уезжает вместе с кодом. Попутно: `tests/test_roles.py` —
герметизация двух тестов (`monkeypatch ONTOSHIP_HOME`): они читали реальный
user-слой, созданный `/roles set` в ходе рана; красная суита блокирует луп,
чинится на месте в этой же ветке.

**Отгружено (2026-10-01).** Коммит `40358e8` (worktree `ship/queue2-06-code-review`),
ff-мерж в main, релиз `v0.5.7` (`03fbd44`), пин (`8d555ab`), self-update — вендор
`skills/code-review` (новый маппинг) совпал с рабочим деревом, `gitmark version`
0.5.7. Приёмочные прогоны на реальном диффе: два до разбивки (14 находок, все
verified) и финальный на пер-файловой архитектуре — 10/10 файл-задач, 9 находок →
4 verified / 5 опровергнуты конфирмерами (критерий verified/unconfirmed доказан
живьём). Ревью тикета: пять self-прогонов собственным инструментом (11→8→5→4
уникальных находок, все закрыты; сходимость на эвристике redact) плюс гейт шага 6 —
3 находки: 2 в conclusion-покрытии исправлены (честная строка покрытия: обе оси /
одна ось / oversized-пропуски), redact-блэклист доработан по хвосту суффикса
(`\b` не встаёт перед `_` — `password_reset_url` маскировался; переработан на
захват хвоста до разделителя, 16 node-кейсов; первый тест был порочен — значение
короче порога `{4,}` не могло срабатывать вовсе). Одно опровержение записано
честно: находка ревьюера о compound keys частично опиралась на устаревшую
скомпилированную копию прогона. Гейт шага 6 также живьём показал слабость
монолитного reviewer-гейта (агент искал дифф в основном чекауте — промпт без
`-C`) — аргумент тикета 13, заведённого в этом же диффе вручную (решение
оператора «разбивка всегда», post-publish дробление зашипленной единицы).
Отклонения: dev-ветки нет — suite на ветке до мержа и на main после (lint,
pytest 72, deploy-check rc=0); подтверждения мержа и деплоя одним сообщением
«continue и деплой»; self-прогон 4 остановлен оператором (потолок self-ревью),
возобновлён словом «запускай продолжи».
