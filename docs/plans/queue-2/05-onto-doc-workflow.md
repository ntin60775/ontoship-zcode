# 05: onto-doc workflow — fan-out кураторов + lint-гейт

**What to build:** док-задача исполняется workflow: план правок расходится
fan-out по кураторам (каждый ведёт свой кусок KB), собранный результат проходит
`gitmark lint` как гейт, провалившееся лечится циклом долечивания до зелёного.
Оператор получает долеченную, линт-чистую правку KB, а не черновик.

**Blocked by:** None (can start immediately).

- [x] workflow-файл существует и запускается на реальной док-задаче в этом репо:
      fan-out кураторов, сборка, lint-гейт после сборки
- [x] цикл долечивания доводит прогон до зелёного `gitmark lint` или честно
      репортит потолок попыток
- [x] `gitmark lint` + `pytest` зелёные

**Отгружено (2026-10-01).** Коммит `2f81507` (worktree `ship/queue2-05-onto-doc`),
ff-мерж в main, релиз `v0.5.6` (`b76c406`), пин (`5573fc1`), self-update — вендор
`skills/doc` совпал с рабочим деревом, `gitmark version` 0.5.6. Приёмочный прогон —
первая работа workflow, дважды: создал service-док канала доставки
(`docs/services/deploy/README.md`) и reference-док ролей (`docs/reference/roles.md`)
с индексными строками; повторный прогон финальной версии подтвердил приёмку на
отгружаемом коде и нашёл/исправил 3 новые фактические неточности доков (кураторы
сверяли с кодом живыми прогонами). Ревью: 6 находок, все независимо подтверждены —
5 в workflow (приёмка доказывалась не для отгружаемой версии; pre-index без гейта
exitCode и без `--root` в поисках кураторов — тихая деградация воспроизведена;
невалидные куски и дубликаты path шли кураторам; отказ куратора/healer рушил прогон),
1 в доке ролей («отступы ровно 2 и 4» — парсер принимает ≥4). Все закрыты.

сообщением «continue и деплой» (деплой без мержа невозможен, слово одно).
