# onto-doc parity — бутстрап, карта, мастер-индекс и покрытие

## Goal

Догнать слой heuristics онто-дока до контракта апстрима: zcode-воркфлоу исполняет
полный цикл «KB из кода» — survey и декомпозиция при пустом плане, карта и coverage
в финале, индексная цепочка под инвариантом линта — не сужая текущего контракта
«готовый план → линт-чистое исполнение».

## Done

- Живой прогон воркфлоу без `args.plan` на фикстуре (tmp: `git init` + копия
  `skills/{kb-search,kb-curate,doc}` + `docs/ontology.md` — байт-твин
  `skills/kb-curate/ontology.md` + материал survey; критерий: `lint` фикстуры
  зелёный до прогона) поднимает KB: зоны по канону апстрима
  (services / reference / ops / decisions), `gitmark lint` зелёный,
  `docs-map.html` создан, отчёт несёт coverage до→после (плоская дельта
  `gitmark stat`: files/chunks/links) и зоны, требующие человека (суждение
  surveyor/кураторов, как в апстриме).
- Прогон с готовым `args.plan` даёт прежнее поведение (куски, healer-цикл,
  прежний отчёт) — обратная совместимость доказана прогоном, а не рассуждением.
- lint: I10 в body-семантике (индексные строки-ссылки в теле README, цепочка
  родитель → подраздел; frontmatter не участвует) — удаление body-ссылки на
  подраздел из README родителя даёт красный с именем инварианта, восстановление
  строки гасит; на этом репозитории `lint --strict` зелёный с I10 — включая
  twin-проверку онтологии — и `pytest` зелёный.
- Реестр планов: перевод плана в `status: archived` без перегенерации реестра
  даёт красный `lint --strict` (I7-механизм `inventory --check`), прогон
  `inventory` гасит; на этом репозитории после синка зелёный. Носитель статусов
  один — генерат-таблица; проза «Порядка выполнения» без статусных клеймов.
- Рассинхрон реестра, внесённый правками прогона онто-дока, гасится хвостом
  прогона (`inventory` рядом с `index`), healer не зацикливается, — приёмка
  прогоном с намеренно внесённым рассинхроном.

## Scope

- `skills/kb-search/gitmark.py` — инвариант I10: цепочка body-индексных строк
  README от `docs/README.md` через каждый подраздел; inventory-таргет «планы» —
  новый first-class таргет со своим сканером (файл-планы и папки, агрегация
  статусов и счётчиков тикетов из frontmatter) и рендером по marker-парам в
  `docs/plans/README.md`; `inventory --check` / I7 ловят рассинхрон; тесты в
  `tests/`.
- `skills/doc/onto-doc.workflow.ts` — surveyor-фаза при пустом `args.plan`
  (survey + декомпозиция — шаги 1–2 канона апстрима; выход surveyor'а проходит
  тот же validation gate: куски, дубликаты); entry-point фаза — AGENTS.md-only;
  tail: `gitmark map` после зелёного линта, `inventory` рядом с `index`,
  coverage (stat-дельта) и зоны-для-человека в отчёте; healer-промпт получает
  inventory-инструкцию как фолбэк.
- `skills/kb-curate/ontology.md` и `docs/ontology.md` — документация I10 в обоих
  twin'ах (twin-проверка линтом).
- `docs/plans/README.md` — секция реестра на генерате; проза «Порядка
  выполнения» — только ordering-решения оператора.
- `docs/README.md` и README-индексы — приведение под I10 при красной пробе
  (проба 2026-10-08 зелёная).
- Вендор `.zcode/` руками не правится — доедет self-update на шаге деплоя.

## Constraints

- `stop-before-commit` (дефолт).
- Entry point — только AGENTS.md; CLAUDE.md не создавать и не упоминать
  (surveyor берёт из канона апстрима только шаги 1–2).
