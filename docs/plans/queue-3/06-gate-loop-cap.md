# 06: ship — критерий остановки гейт-лупа: кап 3 раунда

**What to build:** в `/ship` (шаг 6, скилл `.zcode/skills/ship/SKILL.md`)
появляется явный критерий окончания гейт-лупа: **максимум 3 раунда**
review→confirm→fix на тикет; чистый раунд (0 verified) завершает луп
досрочно. На исчерпании капа исполнитель **не** запускает следующий раунд
сам: состояние приносится на стоп-поинт с историей раундов (счётчики
verified/unconfirmed/unverified на раунд, что закрыто, что осталось), и
решение — добить (явный «continue» оператора открывает ещё один раунд),
принять остатки или оформить хвосты тикетами — за оператором.

**Blocked by:** —.

Решение оператора 2026-10-15 (прогон queue-3/02, r4): выбран «кап 3 раунда»
из трёх вариантов. Порог severity («продолжать только при verified medium+»)
отвергнут живыми данными этого же прогона: r3 был low-only, а r4 принёс два
medium в движке (секрет в argv-пути утекал в сообщение отказа; находка
«третья форма» — опровержима, но вторая — нет) — порог остановился бы после
r3 и пропустил их. Гибрид «кап + low-выход» наследует тот же риск.
Прецедент сходимости: queue-3/01 — 3 раунда; цена раунда ≈900К токенов и
≈11 минут. Источник: ретро-заметка самого прогона («у скилла нет жёсткого
лимита раундов») + указание оператора «должен быть чёткий критерий когда
закончить».
