# 02: lint — несуществующий path-аргумент молча даёт полный прогон

**What to build:** `gitmark lint --strict <path>` валидирует path-аргументы:
несуществующий путь — именованный отказ и ненулевой exit, а не молчаливый
полный прогон KB с «чисто»; семантика фильтрации по существующим путям
(сводка считает весь KB или выборку) фиксируется исследованием и
задокументируется по факту.

**Blocked by:** —.

Наблюдённое поведение (живая проба 2026-10-15, фикстурная проба
behavior-reel/04): `python3 skills/kb-search/gitmark.py lint --strict
docs/plans/nope.md` → `✓ чисто (115 файлов · —)`, exit 0 — то же, что без
аргумента; `cmd_lint` строит `sel = set(paths)` без проверки существования.

- [ ] Семантика зафиксирована: что сегодня делает фильтр по путям (выборка
  файлов против полной сводки), именовано по коду — до правки.
- [ ] Несуществующий путь → именованный отказ с путём в сообщении и ненулевым
  exit; живая проба в тикете.
- [ ] Существующий путь → прежнее поведение (вывод и exit не изменены);
  живая проба в тикете.
- [ ] Тест с негативной пробой (мутация: проверка существования снята — тест
  краснеет); pytest и lint --strict зелёные, лог прочитан.
