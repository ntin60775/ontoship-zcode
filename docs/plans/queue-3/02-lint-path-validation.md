# 02: lint — несуществующий path-аргумент молча даёт полный прогон

**What to build:** `gitmark lint --strict <path>` валидирует path-аргументы:
несуществующий путь — именованный отказ и ненулевой exit, а не молчаливый
полный прогон KB с «чисто»; семантика фильтрации по существующим путям
(сводка считает весь KB или выборку) фиксируется исследованием и
задокументируется по факту.

**Blocked by:** —.

Наблюдённое поведение (живая проба 2026-10-15, фикстурная проба
behavior-reel/04): `python3 skills/kb-search/gitmark.py lint --strict
docs/plans/nope.md` → `✓ чисто (115 файлов · —)`, exit 0 — то же, что без
аргумента; `cmd_lint` строит `sel = set(paths)` без проверки существования.

## Семантика фильтра (исследование по коду, до правки)

`sel = set(paths)` (gitmark.py:794) сужает **только** второй цикл по файлам
(`if sel and rel not in sel: continue`, :838) — per-file проверки I1, I2, I3,
I6. Сквозные проверки фильтра не видят: I4 (битые ссылки, :803–828 — граф
связей строится по всем файлам), I5 (README папок, :830–834), I7 (:877),
I8 (:881), I9 (:883), I10 (:885). Сводка `checked: len(docs)` (:890) всегда
считает весь KB, даже при выборке. Живая проба: `lint --strict <существующий
путь>` байт-идентичен полному прогону — `✓ чисто (121 файлов · —)`, exit 0.
Несуществующий путь → пустая выборка → per-file проверки молча пропущены,
сквозные чисты → неотличимо от полного прогона.

Край, оставленный как есть (существующий, но не совпадающий путь): папка
(`docs/plans`), `./docs/x.md`, абсолютный путь — существуют, проходят
валидацию, но exact-сравнение с rel-путями файлов выбирает 0 файлов; per-file
проверки молча пропускаются. Отказ — только для несуществующих (скоуп
тикета); край именован здесь для будущего решения оператора.

## Решение

Отказ в движке: `cmd_lint` первым делом проверяет `(root / p).exists()` для
каждого path-аргумента; отсутствующие → `ValueError("путь не найден: …")` со
всеми путями в сообщении. CLI ловит и печатает `gitmark: путь не найден:
<path>` в stderr, **exit 2** — класс usage-ошибки argparse, отделён от
exit 1 = ERR онтологии при --strict. Справка path-аргумента называет отказ.
