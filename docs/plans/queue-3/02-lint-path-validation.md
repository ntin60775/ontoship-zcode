# 02: lint — несуществующий path-аргумент молча даёт полный прогон

**What to build:** `gitmark lint --strict <path>` валидирует path-аргументы:
несуществующий путь — именованный отказ и ненулевой exit, а не молчаливый
полный прогон KB с «чисто»; семантика фильтрации по существующим путям
(сводка считает весь KB или выборку) фиксируется исследованием и
задокументируется по факту.

**Blocked by:** —.

Наблюдённое поведение (живая проба 2026-10-15, фикстурная проба
behavior-reel/04): `python3 skills/kb-search/gitmark.py lint --strict
docs/plans/nope.md` → `✓ чисто (115 файлов · —)`, exit 0 — то же, что без
аргумента; `cmd_lint` строит `sel = set(paths)` без проверки существования.

## Семантика фильтра (исследование по коду, до правки)

`sel = set(paths)` (gitmark.py:826) сужает **только** второй цикл по файлам
(`if sel and rel not in sel: continue`, :870) — per-file проверки I1, I2, I3,
I6. Сквозные проверки фильтра не видят: I4 (битые ссылки, цикл по всем файлам
:835–857), I5 (README папок, :863–866), I7 (:907), I8 (:911), I9 (:914),
I10 (:917). Сводка `checked: len(docs)` (:922) всегда считает весь KB, даже
при выборке. Живая проба: `lint --strict <существующий путь>` байт-идентичен
полному прогону — `✓ чисто (121 файлов · —)`, exit 0. Несуществующий путь →
пустая выборка → per-file проверки молча пропущены, сквозные чисты →
неотличимо от полного прогона. Нумерация строк — по финальному дереву
(обе вставки guard'ов уже в файле); сами конструкции фильтра правкой не
тронуты.

## Решение

Два guard'а закрывают один вред — молчаливую пустую выборку с «✓ чисто»
(класс вреда один, форм две):

1. **Несуществующий путь** (guard 1, :791–809): `cmd_lint` проверяет
   `(root / p).exists()`; отсутствующие → `LintPathError` («путь не найден:
   …» всеми именами, whitespace-only — заглушка «(пустой аргумент)», иначе
   C0-стрип делает имя невидимым). stat-отказ (EACCES) — не «не найден»:
   решение остаётся за guard 2 по rel-индексу (на Python 3.13 pathlib при
   EACCES поднимает PermissionError, а не False — проба конфирмера r2).
2. **Существующий, но невыбираемый путь** (guard 2, :810–816, расширен по
   итогам гейта r1): путь есть на ФС, но строкой не совпадает ни с одним
   rel из `iter_md` — каталог, «./»-префикс, абсолютный, gitignored, пустая
   строка — → `LintPathError` («путь не выбирает ни одного файла KB: …»,
   пустая строка — «(пустой аргумент)»). Исследование r1: pathlib-семантика
   (`root / ""` == root, абсолют вытесняет root) проводит эти формы мимо
   exists()-проверки, а sel-сравнение — точная строка.

Оба guard'а стоят до печати gitignore-WARN и до всего анализа (stderr
отказа одного класса — только отказ; rels_set строится один раз, не по разу
на каждый argv-путь). Отказ — именованный класс `LintPathError(ValueError)`
(:782), а не голый ValueError: CLI ловит только его (будущие ValueError тела
lint остаются внутренними ошибками, не переклассифицируются в usage-отказ —
запинено поведенческим кейсом с мутант-ловушкой на except-оговорку). CLI
печатает `gitmark: <msg>` в stderr с **exit 2** (usage-класс argparse,
отделён от exit 1 = ERR онтологии при --strict) и вырезает из сообщения
управляющие целиком: C0/DEL и C1 (U+0080–U+009F — 8-битные CSI/OSC/NEL
доживают до UTF-8-терминала), включая переводы строк (argv-путь —
недоверенный текст на границе вывода; строже, чем redact_lite для msg,
который переводы сохраняет). Справка path-аргумента называет оба отказа.

## Живые пробы (после правки, чекаут worktree)

- `lint --strict docs/plans/nope.md` → stderr `gitmark: путь не найден:
  docs/plans/nope.md`, **exit 2**, stdout пуст.
- `lint ""` / `lint docs/plans/` / `lint ./docs/README.md` / `lint
  /etc/passwd` → `gitmark: путь не выбирает ни одного файла KB: …`, exit 2
  (до r1 все четыре молча давали «✓ чисто», exit 0 — воспроизведено
  конфирмером на KB с I1-нарушением).
- `lint --strict docs/plans/queue-3/02-lint-path-validation.md` → exit 0,
  вывод **байт-идентичен** базовой линии, снятой до правки (diff пуст;
  перепроверено после фиксов r1).
- Мультипуть `docs/plans/nope.md docs/either.md` → оба имени, exit 2;
  смешанный набор (существующий + отсутствующий) → exit 2, в сообщении
  только отсутствующий.
- C0/ESC: `lint $'docs/\x1b[2Jnope'` → 0 байт 0x1b в stderr, одна строка.
- Мутации (cp-бэкап, guard → pass): снятие guard 1 — 4 теста красных,
  снятие guard 2 — 6 красных (5 невыбираемых форм + CLI-каталог), мутант
  `except ValueError` вместо `except LintPathError` — краснет ровно
  поведенческий кейс except-оговорки; восстановление — 21/21.
- Матрица `tests/test_lint_paths.py` 21 кейс: отказы движка по обоим
  guard'ам (параметризация 5 форм, вкл. gitignored — единственная форма,
  отличающая rel-индекс от диска), мультипуть, смешанный набор,
  whitespace-заглушка guard 1, именованный класс ≠ catch-all
  (статика + поведенческий кейс с мутант-ловушкой), семантика фильтра
  представителями семей (per-file I1/I2/I3/I6 сужаются; сквозные
  I4/I5/I7/I9/I10 и checked — весь KB; I8 — именованное исключение:
  требует онтологию-близнеца пакета, в tmp-фикстуре недостижим),
  CLI-каналы exit 2/1/0 (в т. ч. без --strict), stdout пуст при отказе,
  C0/DEL/C1-стрип. Сьют **316 passed**, `lint --strict` чист (121 файл),
  логи прочитаны.

## Гейт r1 (review dwfrun-015e79ee → confirm dwfrun-e14d11b6)

10 сырых находок → confirm **10 verified / 0 unconfirmed / 0 unverified**.
Закрыты: пустая строка и существующий-но-невыбираемый путь (слито в guard 2),

## Гейт r2 (review dwfrun-ec8cfa39 → confirm dwfrun-b86b657f)

10 сырых → confirm **9 verified / 1 unconfirmed / 0 unverified**. Закрыты:
C1-управляющие U+0080–U+009F в стрипе (8-битный CSI/OSC/NEL доходили до
stderr нетронутыми — расширен класс до `[\x00-\x1f\x7f-\x9f]`); поведенческий
кейс except-оговорки (мутант `except ValueError` проходил все 18 кейсов);
gitignored-форма guard 2 (единственная, отличающая rel-индекс от диска —
добавлена в параметризацию); I6/I9 (живые мутации «вынос I6 из-под sel»,
«заворот I9 в sel» были зелёными — запинены кейсами); DEL \x7f в стрип-пробе;
set(rels) на каждый argv-путь (hoist); gitignore-WARN перед отказом guard 2
(guard'ы перенесены до печати WARN); whitespace-only аргумент guard 1
(заглушка «(пустой аргумент)», как у guard 2). Unconfirmed (опровергнута в
посыле): «exists() глотает OSError → EACCES сообщается как "не найден"» — на
Python 3.13 pathlib при EACCES поднимает PermissionError; но проба конфирмера
показала родственный дефект моего диффа — EACCES-путь давал сырой
PermissionError-краш; закрыт: stat-отказ передаётся guard 2 (rel-индекс
решает без ФС-обхода), именованный отказ вместо краша.
