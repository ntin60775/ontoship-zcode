## Goal

Хвосты и проблемы, всплывающие в шипах, живут тикетами этой очереди, а не
строками Ship facts и не памятью агента. Очередь — парковка с правилом
пополнения: ближайший объявленный источник — ship `flow-continuity` (решение
оператора 2026-10-15: «сделай, заодно накидаем туда проблем, что возникнут
при шип flow-continuity»).

## Done

- Оба стартовых тикета отгружены (по своим критериям приёмки).
- Правило пополнения соблюдено: каждая новая проблема из шипа — тикет `NN+1`
  `draft` с источником (ран/Ship facts/живая проба) в день находки, а не
  строка в памяти.

## Правило пополнения

- Новая проблема шипа (гейт-находка класса «граница», side-наблюдение,
  отложенное переромановкой решение) → тикет `NN+1` со статусом `draft`,
  `updated: today`, источником и наблюдаемым поведением; грилл на момент
  записи не требуется — тикет проверяется своим `/ship`.
- Тикеты очереди независимы (без линейности), если сам тикет не объявит
  `Blocked by`; `/ship` берёт первый незашхипленный по `NN`.
- Очередь не заменяет решения оператора: кандидат, требующий выбора механики,
  везёт в тикете варианты и источник решения.

## Scope

- Стартовые тикеты 01–02 (источники — Ship facts roles-per-agent/02 и
  behavior-reel/04).
- Тикеты, добавляемые из шипов по правилу пополнения; первый объявленный
  источник — ship `flow-continuity`.

Вне scope: расширение инвариантов/реестров сверх моратория без записанного
инцидента; полная матрица redact (см. тикет 01 — только лёгкий набор).

## Constraints

- `stop-before-commit` (дефолт) — на каждый тикет очереди.
- Мораторий по прецеденту evidence-discipline: новые механизмы движка,
  I-коды, node_type, роли — не появляются; послабления — явным перечнем в
  самом тикете (прецедент queue-2).
- План создан напрямую из хвостов без грилла (прецедент gate-followups-2);
  грилл отдельного тикета — по необходимости на его шипе.
