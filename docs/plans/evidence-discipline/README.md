# Дисциплина доказательств — телеметрия прогона, обязательность проб, иерархия справкой

## Goal

Проверка результата агента в поставляемых ритуалах ранжирует доказательства
явно: зелёный rc тест-прогона не считается фактом приёмки без прочитанного
лога; новая тест-матрица без негативной/мутационной пробы не считается
доказательством; иерархия «проба над проверкой → живой E2E-ран → зелёный
тест с прочитанным логом → утверждение агента» записана справкой
docs/reference с механизмами, которые её держат.

## Done

- skills/ship/SKILL.md, шаг 5 «Tests» — правило телеметрии: прогон сьюта
  считается фактом, только когда его лог прочитан (первый упавший, счётчики,
  предупреждения; фильтрация вывода не съедает rc — урок «pytest | tail»);
  rc=0 без чтения лога — активность, не факт. Текст — по-английски, в стиле
  соседних строк шага.
- skills/to-tickets/SKILL.md, DoD-проход (шаг 4) — уточнение критерия-факта:
  для «прогона тестов» фактом является прочитанный лог прогона, а не сам
  запуск; расширяет существующее «activity rather than an observable fact».
- skills/ship/SKILL.md, шаг 5 — правило обязательности пробы: новая
  тест-матрица отгружается вместе с негативной/мутационной пробой (кейс,
  который обязан падать при сломанном поведении); матрица без пробы — не
  доказательство. Прецеденты названы: test_redact_matrix.py,
  test_verdict_matrix.py, проба одноразовости extractParts.
- docs/reference/evidence-hierarchy.md — справка «Иерархия доказательств» в
  стиле review-invariants.md: каждый уровень с механизмом, который его
  держит (confirm-ран с пробами; шаг 8 ship + живые приёмки self-update и
  A/B; шаг 5 с правилом телеметрии; гейт и слепота против самоотчёта).
- `gitmark lint --strict` зелёный; вендор skills доехал self-update'ом;
  `scripts/deploy-check.sh` exit=0.

## Scope

- skills/ship/SKILL.md — шаг 5, оба правила.
- skills/to-tickets/SKILL.md — DoD-проход, одно уточнение.
- docs/reference/evidence-hierarchy.md — новый документ.

## Constraints

- `stop-before-commit` (дефолт).
- Мораторий инвариантов движка: правила живут прозой скиллов и справкой,
  новых механизмов lint/inventory/воркфлоу нет.
- Механика гейта (reviewer/confirm воркфлоу) не меняется — план про тексты
  ритуалов, не про код рана.

## Context

- Источник: разбор заметки о TDD и агентах (Kun Chen, DeepSWE; arXiv
  2603.07084 «Countdown-Code», 1% SFT-контаминации) в сессии 2026-10-09;
  решение оператора — «оформи тикетами в рамках одного плана». Ссылки:
  https://x.com/kunchenguid/status/2108030810691629403,
  https://arxiv.org/abs/2603.07084.
- Проверяемое ядро заметки уже реализовано: инварианты 3/4/7
  review-invariants.md (подтверждение свежей моделью, отказ ≠ опровержение,
  тишина ≠ успех), DoD «факт третьей стороны, активность — не критерий».
  План закрывает три незакрытых места из того же разбора:
  1) правило «прогон теста = телеметрия, читать лог» живёт уроками памяти
     («pytest | tail съедает rc»), но не записано в поставляемых текстах;
  2) обязательность негативной/мутационной пробы для новой тест-матрицы —
     прецедентная практика (redact, verdict, extractParts, A/B-проба
     confirm), без правила;
  3) иерархия доказательств нигде не собрана в один текст с механизмами.
- Грилл плана не гонялся: план оформлен по явному запросу оператора из уже
  разобранного анализа; квиз-гейт to-tickets (шаг 3) остаётся точкой
  утверждения разбивки.
