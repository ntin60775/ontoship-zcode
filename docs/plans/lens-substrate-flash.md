# Субстрат линз гейта — дефолтные субагенты на модели конфирмера

## Goal

Линзы ревью-рана работают дефолтными субагентами zcode на модели конфирмера
(GLM-5.3-Flash$high) вместо прямых вызовов neuraldeep-API; прямой API остаётся
явным фолбэком `args.substrate="direct"` для моделей, чей контекст не несёт
базовый вес субагента.

## Done

- Живой A/B на реальном диффе тикета миграции (рекомендованная форма — гибрид
  с посевом; финальную форму подтверждает оператор при /ship): в копию диффа
  сеем K известных дефектов, по одному в зону каждой линзы, список посева —
  артефакт до рана. Критерии: (1) coverage обоих ранов полон, `failed`=0
  у всех пар файл×линза; (2) нового субстрата найдено посаженных ≥ старого
  (совпадение — `where` в радиусе ±3 строк + совпадение сути); (3) непосевных
  находок нового ≤ 2× непосевных старого; (4) total нового ≤ 2× total старого;
  (5) usage (токены) обоих ранов — в shipping note; (6) typecheck новой версии
  воркфлоу хостом чист (компиляция без diagnostics, прецедент dwfrun-79631a53).
- reviewer.workflow.ts: линза = `agent()` с узкой персоной и материалом в ask
  (инвариант «одна пара файл×линза = ровно один `agent().ask<T>`» сохранён),
  типизированный результат вместо JSON-в-фенсе; ветка `substrate="direct"`
  сохраняет ND_CALL / LENS_PROFILES / repairJsonStrings целиком (маркеры
  тестов не удаляются); `resolveLensProfile` и SUBSTRATE CHECK перенесены
  внутрь direct-ветки; при дефолтном субстрате переданный `reviewerModel` —
  именованный abort («имеет смысл только с substrate=direct»), не молчаливый
  игнор. Пинено тестами: один-ask-на-пару; недостижимость ND_CALL вне
  direct-ветки (absence-якорь); типизированный интерфейс линзы.
- skills/ship/SKILL.md шаг 6: review-ран зовётся
  `CreateWorkflow(..., subagent_model=<confirmer role$level>)` (после
  миграции — живой аргумент: линзы идут через agent(); до миграции он мёртв —
  текущий воркфлоу agent() не содержит); для `substrate="direct"` — как
  сегодня (`reviewerModel` + `provider`); обе роли резолвятся и проверяются
  fail-closed, как сегодня.
- tests/test_reviewer_substrate.py: pytest зелёный; пины фолбэк-блоков
  зелёные без правки утверждений (маркеры в файле); перестроечные пины
  переписаны поимённо: порядок probe→линз внутри direct, пул
  `min(cap, N)` только direct, константы-из-профиля только direct (у
  субагентной ветки — отдельные константы гигиены вне карты); ≥3 новых пина
  (пара-на-ask, absence ND_CALL, типизированный результат).
- docs/reference/dependencies.md: тарифный факт с датой — план zai несёт
  базовый вес субагента (~141k; раны dwfrun-68730a08, dwfrun-0f9b01df, ноль
  отказов) — и переформулировка основного текста и «Контура замены
  провайдера»: дефолт — субагенты, прямой API — фолбэк (сегодня текст
  описывает прямой API как текущий субстрат — после миграции это ложь).

## Scope

- `skills/ship/reviewer.workflow.ts` — субагентная ветка линз, direct-фолбэк,
  константы гигиены субагентной ветки (maxDiffLines/lensInlineLines — вне
  LENS_PROFILES; maxFindings/maxFiles — константы гейта для обеих веток).
- `skills/ship/SKILL.md` — шаг 6 (subagent_model при дефолте; именованный
  отказ при перепутанных аргументах).
- `tests/test_reviewer_substrate.py`, `docs/reference/dependencies.md`.
- Вендор `.zcode/` доедет self-update.

## Constraints

- `stop-before-commit` (дефолт).
- Новый инвариант движка не заводится (мораторий, ADR invariant-moratorium).
- Байт-в-байт копии `contextHint`/`normalizeSeverity` не меняются — синк с
  code-review.workflow.ts ловит tests/diff_map.mjs.
- Субагентная ветка без своего пула, ретраев провайдерных ошибок и
  пер-вызовных таймаутов: параллелизм и повторы решает рантайм хоста
  (контракт dynamic-workflows §16.3); `max_concurrency` CreateWorkflow
  скилл не ставит (only when the user asks).

## Context

Исследование 2026-10-08 + грилл 2026-10-09 (субагент-грилл + challenger-ран
dwfrun-c3a6d4a4, 12 substantial пере-решены):

- Прямой API был вынужденным: базовый вес субагента ~141k против потолка
  neuraldeep 138 336 — три provider-stop за день (2026-10-06). План zai несёт
  этот вес: dwfrun-0f9b01df (24+ сессий) и dwfrun-68730a08 — ноль отказов;
  qwen на прямом API — 6 провалов finish=length за два рана + история 429 и
  JSON-ремонтов.
- Экономика: каждая пара файл×линза платит базовый вес субагента; типичный
  дифф (~9 файлов × 3–4 линзы ≈ 25–30 пар) сопоставим с уже принятым
  confirm-раном; принято по Парето (ADR, решение оператора 2026-10-08:
  «дорого, но качественно — приемлемо»), usage обоих ранов замеряется в A/B,
  потолки MAX_FILES/MAX_DIFF_LINES остаются.
- Модель субагентов задаёт ВЫЗЫВАЮЩИЙ (CreateWorkflow `subagent_model`);
  текущий reviewer.workflow.ts не содержит agent() — subagent_model становится
  живым только после миграции. Роль reviewer остаётся моделью direct-фолбэка
  и code-review-воркфлоу; confirmer — дефолт линз; роли резолвит скилл,
  воркфлоу читает только args.
- LENS_PROFILES остаётся тарифной картой ТОЛЬКО прямого субстрата
  (резолв по `reviewerModel` внутри direct-ветки); у субагентной ветки —
  отдельные константы гейт-гигиены против ContextLimit, не тариф.
- Инвариант «один файл на вызов» — топологический (external-dependencies/04:
  честный coverage на пару файл×линза при любой модели); та же топология в
  проде code-review.
