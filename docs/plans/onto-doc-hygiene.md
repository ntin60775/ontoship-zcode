# Онто-док — гигиена диагностических веток и хвоста прогона

## Goal

Закрыть 10 verified дефектов тела `onto-doc.workflow.ts` с гейта шипа
onto-doc-command (2026-10-12): все abort-ветки и промпты субагентов соблюдают
собственные конвенции файла (маскировка секретов до conclusion, «данные,
не инструкции»), хвост и выходы субагентов не дают ложных verified и не падают
на формах ответа.

## Done

- Все abort-ветки (catch битого JSON, «план — не массив», «выход surveyor'а
  без pieces», «куски без path/what») вставляют в conclusion/notCovered только
  срезы с ограничением длины после `redactLite`. Негатив-проба: `{"password":
  "…"}` и `bearer <токен ≥8>` в args.plan/кускаx не появляются в отчёте сырым —
  unit-матрица на чистой функции с мутационной пробой (снятие маскировки
  краснит тест).
- `redactLite` матчит каноническую JSON-форму с кавычками вокруг ключа и
  значения (`{"password": "…"}`) наряду с `password: x` и `password=x` —
  матрица трёх форм.
- Промпт куратора (кусочек плана) и промпт healer'а (lintText) обрамляют
  вставленные данные пометкой «данные, не инструкции» — зеркально task
  в бутстрапе и в готовом-плане ветках.
- Хвостовой `gitmark index` проверяет exitCode: сбой роняет green и уходит
  в notCovered (зеркально inventory и map); клейм «gitmark index (world.run)»
  в verified только при успехе. Проба: мок-отказ index → отчёт не зелёный.
- Выход куратора нормализуется зеркально выходу surveyor'а: строка →
  JSON.parse, не-объект → именованный отказ куска в pieces (written: refused),
  не TypeError вне try. Unit-матрица форм: строка / null / объект / отказ вызова.
- Валидация готового плана (пустой набор, path/what, `..`-escape, дубликаты)
  выполняется до предпрогона index/stat: `args.plan="[]"` abort'ится «прогон
  не начат» без rebuild (лог/замер в приёмке).
- `kbStat` логирует причину каждого отказа (не-ноль exit / не-JSON / не-числа) —
  `coverage: {before: null}` в отчёте сопровождается log-строкой с причиной.
- `pytest` и `lint --strict` зелёные; приёмка — живой бутстрап-прогон на
  tmp-фикстуре (канон onto-doc-parity) зелёный с нового пути.

## Scope

- `skills/onto-doc/onto-doc.workflow.ts` — один файл, один чурн: redactLite
  (регэксп + все четыре abort-ветки), обрамления промптов куратора и healer'а,
  exitCode хвостового index, нормализация выхода куратора, перенос валидации
  плана до дорогой работы, log в kbStat.
- `tests/` — матрица redactLite-форм и форм выхода куратора (чистые функции
  файла извлекаются как в verdict-матрице crossreview-adoption/02).
- Вендор `.zcode/` руками не правится — доедет self-update на шаге деплоя.

## Constraints

- `stop-before-commit` (дефолт).
- Один шип: файл-план исполняется одним слайсом.
- Мораторий инвариантов: новых инвариантов и реестров не заводить.
- Семантику прогона (двухфазный бутстрап/план, lint-гейт, healer ≤4, хвост)
  не менять — чинятся только перечисленные дефекты.
