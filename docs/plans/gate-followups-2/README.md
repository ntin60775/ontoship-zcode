# Контракт: хвосты ship-прогонов

## Goal

Закрыть четыре подтверждённых хвоста из ship-прогонов 2026-10-05 и приёмки
gate-followups/02 (контракт промпта оси синхронен коду — цитата, нормализация
severity не молчит, матрица диффа читает файл один раз, managed-блок `/init`
называет команды так, как они резолвятся в zcode) плюс два хвоста 2026-10-06:
онбординг реестра команд (init его не создаёт) и синхронизация шага 7 скилла
/ship с формализованным git-флоу, плюс перестройка оси гейт-ревьюера: узкие
специализированные линзы вместо «один файл диффа на ревьюера» (решение
оператора 2026-10-06 после двойного provider-stop рана handoff-snapshot/02 —
139k токенов входа при тарифном потолке 138 336).

## Done

- Блок `/init` использует короткие имена команд (`/kb-search`, `/doc`,
  `/ship`) — у нового потребителя блок сразу указывает на существующие
  команды; у живущих — мигрирует бесплатным кейсом замены блока.
- `/init` создаёт скелет реестра команд `docs/reference/commands.md` на
  проекте без него — I7 «реестр не найден» не переживает установку.
- Шаг 7 скилла `/ship` описывает локальный мерж в dev при любом контуре;
  MR — только по явному назначению (со стоп-поинтом `stop-after-mr`);
  Honest degradation ссылается на отступления-константы в docs/ops/git-flow.md.
- Промпт оси код-ревью не обещает механики, которой нет: текст о
  обязательности цитаты соответствует фактическому поведению безцитатных
  находок (направление — enforcement или честная формулировка fallback'а —
  фиксируется на ревью тикета).
- Нормализация severity (вне high/low → medium) считается и называется
  в conclusion обоих review-воркфлоу.
- `tests/diff_map.mjs` извлекает каждый файл-копию один раз за прогон;
  байт-проверки копий и набор кейсов не ослаблены.

## Scope

- `skills/init/SKILL.md` — verbatim-блок и оговорка про префикс; создание
  скелета реестра `docs/reference/commands.md`.
- `skills/ship/SKILL.md` — шаг 7 и Honest degradation (синхрон с
  docs/ops/git-flow.md).
- `skills/ship/reviewer.workflow.ts`, `skills/code-review/code-review.workflow.ts` —
  текст промпта оси про цитату; счётчик нормализаций severity.
- `tests/diff_map.mjs` — кэш извлечения; якоря новых контрактов в матрице.

Вне scope: машинерия гейтов (форма находки, confirm-контракт), ретраи
конфирмера (это crossreview-adoption/02), KB-док инвариантов (03 того же
плана).

## Constraints

- Каждый тикет — полный луп `/ship` со своим релизным циклом (правки
  скиллов вендорятся self-update'ом).
- Слепота review-ранов не задевается: счётчики и правки промптов не
  передают между ранами ничего нового.
- Форма находки гейта `{where, claim, evidence, severity, quote?, axis?}`
  не меняется.

## Context

Все четыре — верифицированные находки или зафиксированные решения, отложенные
сознательно: тройной вызов `extractParts()` — единственная verified-находка
confirm-рана базлайна приёмки crossreview-adoption/01 (2026-10-05, качество
теста, не корректность); severity-коалесинг без лога и обещание обязательной
цитаты без enforcement — verified-находки приёмки gate-followups/02
(2026-10-05, «вне скоупа тикета, кандидаты в фоллоу-апы»); omp-префиксы в
шаблоне managed-блока — порт-дрейф, вскрытый миграцией ut-10 (ADR ut-10
`37cf931c`: короткая форма — правильная, префиксную при `/init` не принимать).
Тикеты 05–06 добавлены 2026-10-06 решением оператора: 05 — живой кейс I7
«реестр не найден» в KB sot-zcode-marketplace (реестр не создаёт никто —
проверено по тексту init-скилла и истории репо; one-off отвергнут оператором
в пользу системного фикса); 06 — расхождение шага 7 («MR when there is») с
формализованным git-флоу (docs/ops/git-flow.md), вскрытое обсуждением
деградаций прогона handoff-snapshot/01. Тикет 07 добавлен 2026-10-06 решением
оператора по итогам гейт-прогона handoff-snapshot/02 (дважды provider-stop):
ревьюер-на-файл — неверная ось разбиения, ревьюеры должны быть максимально
узкими специалистами, каждый со своим маленьким куском; запрет объёмных
команд в персоне (`68367ea`) — симптоматическая мера до перестройки. План
собран вручную из находок
прогонов, без гриллинга (прецедент
gate-followups). Файловых коллизий с crossreview-adoption/02–03 нет (тот
правит confirm-ран и KB-док, этот — review-воркфлоу, init, ship-текст и
тесты); в общем
порядке стоит после него как заявлено.
