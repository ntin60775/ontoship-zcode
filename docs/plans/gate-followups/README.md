# Контракт: фоллоу-апы ship-гейта

## Goal

Закрыть два хвоста прогона queue-2/16: паритет код-ревью с ship-гейтом по
untracked-файлам диффа и устойчивость reviewer-рана гейта к провайдер-стопам
на тяжёлых файлах.

## Done

- `/code-review` ревьюит весь дифф области, включая новые незакоммиченные
  файлы: карта файлов и именованное покрытие — как в ship-гейте после
  queue-2/16.
- Ревью-ран ship-гейта на reviewer-роли user-слоя (neuraldeep qwen) проходит
  дифф с тяжёлым файлом без провайдер-стопа «слишком длинный запрос».

## Scope

- Workflow-скрипты гейта (reviewer/confirm/code-review), тест-матрицы
  парсеров, живые приёмочные прогоны.

Вне scope: смена reviewer-роли в roles.md (операторское решение по квотам),
abort-диагностика args (queue-2/17), порты 1c/unica.

## Constraints

- Парсеры карты диффа живут источником и копиями: копии обязаны быть
  байт-в-байт идентичны и проверяться матрицей (паттерн redact-матрицы
  queue-2/15) — расползание копий ловит тест, не глаз.
- Гигиена контекста не снижает качества ревью: confirm-фаза, лимиты находок
  и именованное покрытие сохраняются; приёмка обоих тикетов — живой прогон
  (прецедент queue-2/16).
- Провайдер-стопы моделей скрипту не видны (фасад останавливает ран вне
  скрипта): рычаг — не порождать переполнение контекста, не retry-логика.

## Context

- queue-2/16 (shipping-note): гейт стал ревьюить 4/4 файла диффа; найдено вне
  скоупа — code-review строит карту тем же numstat-only паттерном, untracked
  выпадают из код-ревью молча.
- queue-2/15 (shipping-note): qwen-400 на тяжёлых файлах дважды; обход —
  черновик-гейт с гигиеной контекста в аске (оператором одобрен); фоллоу-ап
  «устойчивость гейта к провайдер-стопам» остался открытым.
- queue-2/16: второй случай qwen-400 — reviewer-ран дошёл на GLM только
  ручной сменой модели оператором в GUI; roles.md user-слой сознательно
  держит reviewer на neuraldeep (квоты), поэтому тикет 02 делает qwen
  рабочим, а не меняет роль.
