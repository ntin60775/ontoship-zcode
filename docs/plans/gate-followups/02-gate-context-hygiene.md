# 02: Гейт проходит тяжёлые файлы без провайдер-стопа

**What to build:** reviewer-ран ship-гейта на reviewer-роли user-слоя
(neuraldeep qwen) проходит дифф с тяжёлым файлом без останова «Слишком
длинный запрос» — сейчас провайдер отклоняет запрос ревьюера, когда агент
нагоняет контекст полным чтением большого файла (случаи queue-2/15 и /16;
во втором ран дошёл только ручной сменой модели оператором в GUI). Гигиена
контекста в asks гейта: ревью от диффа и адресными чтениями вместо чтения
файла целиком — паттерн одобренного оператором черновик-гейта queue-2/15,
перенесённый в вендоренный скрипт. Провайдер-стопы скрипту не видны (ран
останавливает фасад вне скрипта) — рычаг один: не порождать переполнение
контекста, не retry-логика. Качество ревью не проседает: confirm-фаза,
лимиты находок и именованное покрытие остаются как есть.

**Blocked by:** None (can start immediately).

- [ ] confirm-фаза и именованное покрытие не деградировали — гейт-контракт
