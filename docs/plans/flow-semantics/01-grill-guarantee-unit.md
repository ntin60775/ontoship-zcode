# 01: Правила гарантии грилла и юнита в текстах планирования

**What to build:** вход в планирование гарантирует грилл и юнит. Грилл
принимает наравне с /grilling входы «оформи план» (разговор) и «триаж ишью»
на стадии готового драфта; контракт несёт провенанс-строку в Context (след
грилла: challenger-ран + дата; либо явный opt-out оператора с перечнем
отклонённых пассов: юнит-счётчик, DoD-pass, дайджест) и юнит-якорь: юнит =
набор план-критериев приёмки в Done, независимо от критериев срезов;
разбиваемость на два непустых независимых набора = два юнита = план режется
до публикации. Предикат многослайсности переписан: «юнит строится >1
срезом» вместо счёта независимо шипуемых deliverable; тест «would this ship
as one /ship slice?» сохранён. to-tickets: шаг 0/1 отказывает плану без
провенанса — именованный отказ; критерии срезов несут «каждый срез —
рабочее состояние потребителя» и принадлежность срезов юниту; description —
ручной вход только на гриллованных планах. kb-curate: схема контракта
синхронна с grilling (провенанс в Context, Done = план-критерии юнита).

**Blocked by:** None (can start immediately).

## Поставка (2026-10-16, v0.5.62)

grilling: входы «оформи план» (разговор) и «триаж ишью» наравне с /grilling
(description + шаг 2), свип открытых ишью `.zcode/ontoship/issues/` на входе
(нет папки — пустой свип; триажированная ишью переезжает в контракт, файл
удаляется); провенанс-строка Context — ровно одна: след грилла
(`Провенанс: грилл — dwfrun-<id>, YYYY-MM-DD`) либо явный opt-out с перечнем
отклонённых пассов (challenger — шаг 4; юнит-чек — шаг 7; DoD-pass — шаг 7;
дайджест — шаг 5); юнит-якорь «the unit = the set of plan acceptance criteria
in Done» (некруго, независимо от критериев срезов; разбиваемость на два
непустых независимых набора = два плана до публикации; эпики — ишью);
предикат «юнит строится >1 срезом» (счёт deliverable retired, тест «would
this ship as one /ship slice?» сохранён); односрезный юнит — отчёт называет
одну дорогу (ручной /ship), ручной to-tickets не предлагается.

to-tickets: чек провенанса — первое действие шага 0 (до промоции), именованный
отказ «нет записи грилла/opt-out в Context», разбивка не начинается; тикеты
только из планов (spec/разговор/тема маршрутизируются в грилл — входы из
тела убраны); критерии срезов: «каждый срез — рабочее состояние потребителя»,
«independently shippable» — свойство плана (юнита), не тикета; description —
ручной вход только на планах с провенанс-записью.

kb-curate: схема контракта синхронна (Done = план-критерии юнита, Context
несёт quote-carrier + ровно одну провенанс-строку) — включая полную модель
ontology.md в обеих копиях (I8 идентичен, updated: 2026-10-16) и шаблон
NN-\<ticket-slug\>.md по всем носителям.

  а также несоотвествие ожидаемому для оператора результату .») → Вход:
  оператор просит «оформи план» в разговоре, /grilling не вызывается →
  Наблюдаемый выход: грилл запускается с этого входа наравне с /grilling;
