# 01: Правила гарантии грилла и юнита в текстах планирования

**What to build:** вход в планирование гарантирует грилл и юнит. Грилл
принимает наравне с /grilling входы «оформи план» (разговор) и «триаж ишью»
на стадии готового драфта; контракт несёт провенанс-строку в Context (след
грилла: challenger-ран + дата; либо явный opt-out оператора с перечнем
отклонённых пассов: юнит-счётчик, DoD-pass, дайджест) и юнит-якорь: юнит =
набор план-критериев приёмки в Done, независимо от критериев срезов;
разбиваемость на два непустых независимых набора = два юнита = план режется
до публикации. Предикат многослайсности переписан: «юнит строится >1
срезом» вместо счёта независимо шипуемых deliverable; тест «would this ship
as one /ship slice?» сохранён. to-tickets: шаг 0/1 отказывает плану без
провенанса — именованный отказ; критерии срезов несут «каждый срез —
рабочее состояние потребителя» и принадлежность срезов юниту; description —
ручной вход только на гриллованных планах. kb-curate: схема контракта
синхронна с grilling (провенанс в Context, Done = план-критерии юнита).

**Blocked by:** None (can start immediately).

- [ ] grilling SKILL.md: входы (разговор/триаж ишью), провенанс-строка
  Context в шаблоне контракта, юнит-якорь, предикат «юнит строится >1
  срезом» — grep-якоря на месте
- [ ] to-tickets SKILL.md: description сужен на гриллованные планы; шаг 0/1 —
  именованный отказ без провенанса; критерии срезов — «рабочее состояние»,
  срез внутри юнита
- [ ] kb-curate SKILL.md: схема контракта синхронна (провенанс, Done =
  план-критерии юнита)
- [ ] Живая проба: свежий файл-план без провенанс-строки получает
  именованный отказ на входе /to-tickets
- [ ] Сьют и lint --strict зелёные, лог прочитан

## Reel

- Цель (дословно: «любое оформление плана не важно по какому событию
  подразумевает и его гриллинг сразу, иначе получаем неполноценный план,
  а также несоотвествие ожидаемому для оператора результату .») → Вход:
  оператор просит «оформи план» в разговоре, /grilling не вызывается →
  Наблюдаемый выход: грилл запускается с этого входа наравне с /grilling;
  публикуемый контракт несёт провенанс-строку в Context со следом грилла
  (challenger-ран + дата)
- Цель (дословно: та же) → Вход: /to-tickets на свежем файл-плане без
  провенанс-строки в Context → Наблюдаемый выход: именованный отказ «нет
  записи грилла/opt-out в Context», разбивка не начинается
- Цель (парафраз): гриллованный план проходит вход планирования → Вход:
  /to-tickets на гриллованном плане, в Context — след challenger-рана с
  датой → Наблюдаемый выход: отказ не срабатывает, разбивка начинается
- Цель (дословно: «план обязан поставлять ровно один , целостный и
  минимально неделимый юнит функциональности.») → Вход: план-критерии
  приёмки распадаются на два непустых независимых набора → Наблюдаемый
  выход: грилл режет план на два до публикации — правило юнит-якоря
- Цель (парафраз): якорь юнита не сводится к счёту deliverable → Вход:
  план с несколькими независимо шипуемыми deliverable, план-критерии не
  распадаются → Наблюдаемый выход: план остаётся одним юнитом, строится
  несколькими срезами; счётчик deliverable не применяется
- Цель (дословно: «также и с тутикетс: должно запускаться автоматом если
  план сложный, а если не нужно, то и предлоагать это незачем, иначе только
  вводишь в заблуждение оператора и заставляешь его тратить время на
  задавание тебе контрольнрыйх и наводящих вопросов, чтобы в итоге выяснить
  что тикеты здесь не нужны.») → Вход: гриллованный план, юнит строится >1
  срезом → Наблюдаемый выход: to-tickets идёт автоматом после аппрува;
  тикеты несут «каждый срез — рабочее состояние потребителя» и
  принадлежность срезов юниту
- Цель (дословно: та же) → Вход (краевой): односрезный юнит после аппрува →
  Наблюдаемый выход: автоцепочка завершена, ручной to-tickets не
  предлагается, отчёт называет одну дорогу
- Цель (парафраз): явный opt-out оператора заменяет грилл → Вход
  (краевой): Context несёт явный opt-out с перечнем отклонённых пассов →
  Наблюдаемый выход: план проходит вход без грилла, отказ не срабатывает
- Цель (парафраз): тексты планирования не врут о процессе → Вход: чтение
  to-tickets description и kb-curate схемы контракта после правки →
  Наблюдаемый выход: description — «ручной вход только на гриллованных
  планах»; kb-curate синхронен с grilling (провенанс в Context, Done =
  план-критерии юнита)

Отклонённые случаи контрслоя: нет.
