# Непрерывность флоу (flow-continuity)

## Goal

Убрать из цикла ворота без решения: после утверждённого грилла многослайсный план сам
идёт в /to-tickets той же сессией; перед шипом тикет с устаревшими предпосылками
перегрилливается явно, а не исполняется молчаливой импровизацией. Ручной /ship,
стоп-поинты, гейт и квиз — неприкосновенны.

## Done

- Автоцепочка: после ExitPlanMode-аппрува многослайсный контракт (объявляет тикетную
  структуру) идёт в полный прогон /to-tickets (шаги 0–6) той же сессии — без ручной
  команды между аппрувом и квизом; однослайсный контракт — стоп, как сегодня;
  прерванная сессия — ручной запуск как фолбэк. Живая проба: первый же грилл
  оператора после self-update на многослайсном плане доходит до публикации тикетов
  без копирования команды.
- Шаг 0 /to-tickets переживает незакоммиченный контракт: tracked → `git mv`;
  untracked → mkdir + mv + `git add`. Проба: свежий untracked-контракт проходит шаг 0
  без fatal (живой анти-прецедент: `git mv` на untracked = rc=128).
- Коммит рана разбивки несёт контракт + промоушн + тикеты + порядок + crystallised
  terms (docs/decisions/) одним куском; заявка «без сирот» ограничена многослайсными
  планами — однослайсное окно «записан, не закоммичен» сохраняется сознательно.
  CONTEXT.md в шаге 7 помечен «если ведётся» (файла в репо нет — буква шага была
  неисполнима буквально).
- Descriptions согласованы: grilling (:3) — грилл кончается контрактом
  (однослайс) или тикетами (многослайс), approved via plan gate + квиз; to-tickets
  (:3) — «запускается гриллом после аппрува (полный прогон, шаги 0–6) или вручную на
  любом плане»; «Runs only by hand» снято. Реестр и commands.md регенерированы
  (gitmark inventory), I7 зелёная.
- Ship шаг 1 — ветка дрейфа с проверяемыми триггерами: (i) якорь тикета не находится
  в текущем дереве; (ii) дословный тезис оператора (Context контракта, носитель
  behavior-reel) перестаёт сходиться с реальностью репо по проверяемой команде;
  (iii) явный флаг оператора. Сработал — мини-грилль: пере-решить затронутые
  положения с evidence (grilling:36-38 — evidence или эскалация), одностороннее —
  AskUserQuestion, правка тикета по правилам post-publish (нумерация и рёбра
  сохраняются), ран продолжает. Always-on перегрилль отвергнут.
- Соседний каскад: мини-грилль называет затронутые соседние тикеты (depends_on,
  общие якоря) и перепроверяет их тем же проходом — молчаливого каскадного дрейфа
  нет.
- kb-curate:74-76 переформулировано: to-tickets авторит тикеты; ship-ран правит
  тикет только через ветку дрейфа (именованные правки) — текст KB не врёт о
  процессе.
- pytest и lint --strict зелёные; пины test_run_model_column.py не тронуты.
