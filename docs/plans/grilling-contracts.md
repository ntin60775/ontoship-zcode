# Контракты grilling: id решений и вход «оформи» (grilling-contracts)

## Goal

Два контракта скилла grilling не держат флоу: (1) шаг 3 описывает запись
решения без `id`, а challenger.workflow.ts требует его обязательно — любой
грилл по тексту скилла падает на раздаче имён субагентов
(«challenger-undefined is used twice», живой кейс dwfrun-62a83e74), причём
workflow не валидирует поля вовсе: одиночный пропуск id проходит тихо;
(2) правило входа «оформи» живёт только там, где агент его не читает в фазе
отказа: description не виден до вызова скилла (в списке скиллов — имена и
пути), тело грузится вызовом — а отказ ишью 11 случился до вызова. Грилл
запускается словом оператора или не запускается вовсе.

## Done

1. Шаг 3 skills/grilling/SKILL.md: перечень полей решения начинается с `id`
   и называет его контрактно — «короткий уникальный идентификатор d1…dN,
   из него строится имя субагента челленджа; дубль или пропуск id валит ран
   громко». Grep-якорь в обеих копиях (вендор — после self-update).
2. challenger.workflow.ts: между разбором массива и раздачей имён — громкая
   валидация решений в стиле существующего abort-блока (:53–58/:78–83):
   у каждого решения `id` — непустая строка, id уникальны по массиву;
   нарушение — abort с перечислением битых позиций. Фолбэка авто-id нет —
   падение называет баг вызывающего, не маскирует его.
3. Валидация — чистая функция, покрыта матрицей кейсов (валид; дубль;
   пропуск; пустая строка; не-строка) с мутационной пробой; носитель —
   tests/ по образцу test_lens_routing.py (извлечение чистой функции из
   workflow-файла).
4. Тело SKILL.md несёт правило входа в двух местах: строка в начале
   раздела The flow («оформи», «оформи план», синонимы — равные входы;
   остановка на файле-артефакте без грилла — ошибка маршрутизации) и буллет
   в Invariants по образцу «Evidence or escalate». Grep-якоря.
5. hooks/session-start.sh: одна строка-указатель — вход-фразы («оформи»,
   «погрилл», «триаж ишью») направляют в grilling. Хук печатается в
   контекст каждой сессии — единственный носитель, достающий до фазы отказа
   (до вызова скилла); вывод хука остаётся тихим при отсутствии KB.
6. description: голое «оформи» добавлено в перечень вход-фраз (его там не
   было — отказ случился именно на голой фразе). Зафиксировано: на этом
   хосте description до вызова скилла не виден и маршрутизации не несёт —
   правка честности перечня, не канала.
7. Синтетическая контрактная проба на шипе: чистый ран
   challenger.workflow.ts с args, собранными по новому тексту шага 3
   (одно решение-приманка с id), завершается ok — звено «текст шага 3 →
   контракт Decision», которое grep не проверяет и которое уже отказывало
   при корректном тексте. Факт пробы — в записи плана.
8. Сьют pytest зелёный (включая новую матрицу), lint --strict чист,
   инвентарь реестра перегенерирован.
9. Вендорные копии: после self-update релиза diff трёх файлов
   (SKILL.md, challenger.workflow.ts, session-start.sh) с исходниками пуст;
   deploy-check exit=0.
10. Ишью 09 закрывается на шипе (закрыт-канон после deploy-check и
    self-update — страховка живёт до факта поставки). Ишью 11 шипом НЕ
    закрывается: её закрытие — первый живой «оформи → грилл» в свежей
    сессии после self-update, при снятом или помеченном костыле агентской
    памяти oformi-entry-grilling (иначе прогон докажет память, а не якорь);
    факт пробы — в записи ишью 11.

## Scope

- skills/grilling/SKILL.md — шаг 3 (id), начало The flow и Invariants
  (вход), description (голое «оформи»).
- skills/grilling/challenger.workflow.ts — чистая функция валидации + её
  вызов в существующем abort-контуре; остальной код не трогается.
- hooks/session-start.sh — одна строка-указатель.
- tests/ — новая матрица валидации (файл по образцу test_lens_routing.py).
- .zcode/ontoship/issues/09-…md — статусная строка и закрытие прогоном
  шипа; .zcode/ontoship/issues/11-…md — статусная строка (закрытие вне
  этого среза, Done 10).
- docs/plans/grilling-contracts.md — этот файл-план;
  docs/plans/README.md + docs/reference/commands.md — регенерация
  gitmark inventory.
- Вендорные копии руками не правятся — доедет self-update.

## Constraints

- `stop-before-commit` (дефолт).
- Мораторий (перечнем): правки — два файла skills/grilling/, один хук,
  новая тест-матрица, статусные строки ишью 09/11, этот файл-план,
  регенерат реестра. Ни движка (gitmark.py), ни других скиллов, ни
  deploy.json (hook уже маппится), ни ранбука.
- Релиз: плановая поставка — релизом (полный контур: проза скилла и хук —
  heavy paths) + self-update; dev-канал не назначается — срочности нет.
  Версия не пиннится — «v0.5.66 или следующий patch»: сиблинг
  onto-doc-abort-redact предсказывает ту же версию и стоит в конвейере
  впереди.
- Грилл прожит до шипа (dwfrun-109f9257, 2026-10-18) — требование шага 1
  /ship; провенанс в Context.
