## Goal

Каждый субагент воркфлоу читает модель из назначенной ему роли; роли —
единственный контур LLM субагентов (модель чата больше не рычаг). Общий
дефолт: любая роль без специфики — GLM-5.3-Flash$max (решение оператора
2026-10-13). Назначения для онто-дока: кураторы — GLM-5.3-Flash$high,
сводящий результаты кураторов — GLM-5.3-Flash$max. Матрица контракта
canon/02 и тесты переписаны на новые вводные.

## Constraints

- `stop-before-commit` (дефолт).
- Fail-closed без фолбэка: всё известно заранее — resolve ролей и сверка с
  ListModels ДО запуска, несовпадение = стоп с диагностикой роли и слоя
  (решение оператора 2026-10-13: «всё известно заранее»; вопрос фолбэка
  снят).
- Компиляторский предел хоста (живой эксперимент 2026-10-13, диагностика
  дословно в Context): persona.model обязан быть известен до старта рана —
  строка из args не проходит. Динамические модели роли входят в ран только
  (а) ран-уровневым `subagent_model` (одноролевой прогон) или (б)
  литералами, которые запускающий агент подставил в скрипт после резолва
  (многоролевой прогон). Хардкод model()-литералов в статическом движке
  мимо ролей запрещён вводной «роли проекта задают свою LLM».
- Семантика онто-док прогона (survey → fan-out → lint-гейт → healer ≤ 4 →
  хвост) не меняется — только источник моделей.
- Мораторий инвариантов: новых инвариантов и реестров не заводить.

## Context

- Триггер ревизии: обновление zcode (октябрь 2026) — фасад воркфлоу даёт
  пер-агентные модели (`AgentPersona.model`, `model()`; SKILL.md §2 :106,
  patterns.md #13). Живой зонд: ран без раннего subagent_model, два
  субагента на разных persona-моделях ответили «GLM-5.3-Flash» и
  «Qwen (Alibaba)» (dwfrun-e8132143, v2 dwfrun-43f0a8a8).
- Предел: черновик с `agent(n, { model: String(args.models.probe) })`
  отвергнут компилятором — «A subagent's `model` must be known before the
  run starts: a string literal, a union of string literals, or a ModelRef
  from model("…")». Значит мост «роль → persona» через args невозможен;
  ран-уровень subagent_model хост валидирует на сабмите — он динамический.
- Решение оператора 2026-10-13: (1) рамка — общий механизм «все роли
  проекта задают свою LLM», не патч онто-дока; (2) общий дефолт любой
  роли — GLM-5.3-Flash$max; (3) онто-док: кураторы $high, сводящий
  результатов кураторов $max; (4) фолбэка нет — всё известно заранее;
  (5) матрица и тесты переписываются на новые вводные. Пересматривает
  решение 2026-10-12 (модель чата) его же триггером «явный запрос
  оператора».
- Классы агентов движка онто-дока: `surveyor` (:352), `curator-${i}`
  (:413), `healer` (:476); агента-«сводчика» нет — финальный отчёт
  собирает детерминированный код. Кандидаты на роль «сводящего» (грилл):
  (рекомендация) `surveyor` — единственный «архитектор» прогона, его
  декомпозиция определяет весь fan-out, $max оправдан; воркеры
  (`curator-${i}`, `healer`) — роль `curator` $high. Альтернатива —
  завести нового агента-синтезатора отчёта на $max: меняет семантику
  хвоста, без явной потребности не заводим.
- Способ моста в движке онто-дока (грилл): (рекомендация) движок-шаблон с
  плейсхолдерами `{{ROLE_MODEL:<role>}}`; запуск = resolve+verify →
  детерминированная подстановка литералов в копию под
  `.zcode/workflow-drafts/` → CreateWorkflow(path). Роли остаются
  динамическими (каждый запуск переразолвит), модели видны в окне
  подтверждения, статичный артефакт (шаблон+правило подстановки) тестируется
  и гейтится. Альтернативы отвергнуты: model()-литералы в статическом
  движке (роли не текут), строки из args (компилятор запрещает).
- Одноролевые скиллы (ship, code-review, architecture, grilling) уже
  роль-ориентированы ран-уровнем — не трогаются; их паттерн становится
  документированным «мостом №1».
