# Контракт: внешние зависимости

## Goal

Субстрат гейт-ревьюера на coddy (gate-followups-2/07) ввёл первую
машинно-уровневую зависимость плагина с собственным конфигом, тарифом и
каналом обновления. Закрыть два хвоста (решения оператора 2026-10-07):
(1) цепочка поставки/деплоя/обновлений с учётом coddy — `/roles` становится
единственной точкой руления моделями гейта и правит в том числе конфиг
coddy, команды скиллов пересматриваются под зависимость, машинные
пререквизиты документируются; (2) инвентаризация всех внешних зависимостей —
сторонние решения и апстрим базового онтошипа (ontoship-omp, Ковальский) —
и спроектированный контур обновления на случай их изменения.

## Done

- `/roles` видит и правит модели в `~/.coddy/config.yaml`: resolve показывает
  модель ревьюера в coddy-форме и именует дрейф «роль ↔ конфиг coddy»; set
  правит список models текстуально, не трогая провайдерные ключи.
- Гейт fail-closed по субстрату: нет бинарника coddy / нет модели в конфиге —
  остановка с диагностикой, называющей роль, файл конфига и недостающее.
- `docs/ops/install.md` называет машинные пререквизиты (git, node, python3,
  pytest, coddy) и границу ответственности: раннер вендорит payload в
  проекты, машинные инструменты — пререквизит машины.
- `docs/reference/dependencies.md` — инвентаризация внешних зависимостей:
  апстрим ontoship-omp (gitmark.py, модель онтологии), neuraldeep (API,
  тарифы, потолки), coddy (бинарник, конфиг, канал обновления), zcode-хост
  (воркфлоу, хуки, MCP), маркетплейс-раннер, тулчейн; для каждой — текущий
  пин, канал обновления, владелец решения, деградация при мажоре, где
  ловится.
- Контур обновления апстрима: процедура синка `gitmark.py`/`ontology.md` из
  ontoship-omp (сегодня ручная, прецеденты queue-2) с критериями принятия
  решения.

## Scope

- `skills/roles/roles.py` + `skills/roles/SKILL.md` — чтение/правка
  `~/.coddy/config.yaml` (только список models).
- `skills/ship/reviewer.workflow.ts` — fail-closed диагностика субстрата.
- `skills/ship/SKILL.md` — пересмотр команд шага 6 под зависимость.
- `skills/contour/SKILL.md` (новый) — поставляемые уроки механики
  zcode-workflow/хуков: потребитель не собирает грабли, найденные прогонами
  здесь (тикет 03).
- `docs/ops/install.md` — пререквизиты машины.
- `docs/reference/dependencies.md` — инвентаризация и контур.

Вне scope: смена субстрата confirm-рана (GLM-Flash через сабагентов хоста —
помещается, не трогаем), `code-review.workflow.ts` на coddy (отдельное
решение после 07, как и записано в тикете 07), механика самостоятельного
обновления coddy (его собственный канал, мы только фиксируем версию),
расширение обязанностей маркетплейс-раннера на машинные инструменты.

## Constraints

- Каждый тикет — полный луп `/ship` со своим релизным циклом.
- Креденшелы coddy не покидают его `api_key_command`: `/roles` правит список
  models, провайдерные секции не трогает; в тестах — только структура.
- Ответственность маркетплейса не расширяется: payload внутри проектов
  (пин/validate/update) — его уровень; машинные инструменты — уровень машины,
  документируются, раннером не устанавливаются.

## Context

Стена тарифа 2026-10-06: базовый вес запроса сабагента воркфлоу ~140k токенов
(контракт + схемы инструментов хоста) при потолке neuraldeep 138 336 — три
provider-stop за день, выживаемость первого запроса монетка. Решение
оператора: линзы гейта — одноразовые вызовы coddy (глобальный бинарник,
один провайдер neuraldeep, ноль MCP, ключ через api_key_command), модель —
безлимитный тариф `neuraldeep/qwen3.6-unlim-xl` (строка в конфиге добавлена
по санкции оператора 2026-10-07, живая проба прошла). План собран вручную из
решений оператора, без гриллинга (прецедент gate-followups). Файловых
коллизий с gate-followups-2 (05–07) и crossreview-adoption/03 нет: 01 правит
roles/install/гейт-диагностику, 02 — только новый док.
