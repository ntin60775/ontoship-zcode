# Контракт: внешние зависимости

## Goal

Субстрат гейт-ревьюера (gate-followups-2/07) ввёл первую машинно-уровневую
зависимость плагина с собственным конфигом, тарифом и каналом обновления.
Решение оператора 2026-10-07 (dbda7a9): контур моделей/кредов замыкается на
zcode — карточка провайдера в `~/.zcode/v2/provider_config.json` единственный
источник apiKey/baseUrl; coddy-версия тикета 01 закрыта вместе с coddy-
субстратом. Закрыть два хвоста: (1) провайдер гейта — аргумент, замена
провайдера без правки репо; гейт fail-closed по субстрату; машинные
пререквизиты документируются; (2) инвентаризация всех внешних зависимостей —
сторонние решения и апстрим базового онтошипа (ontoship-omp, Ковальский) —
и спроектированный контур обновления на случай их изменения.

## Done

- Контур моделей/кредов замкнут на zcode (тикет 01, v0.5.31): провайдер
  гейта — аргумент `args.provider` (дефолт `neuraldeep-sub`); замена
  провайдера — карточка в zcode плюс `provider` и `reviewerModel`, без
  правки репо.
- Гейт fail-closed по субстрату: конфиг провайдеров zcode не читается / нет
  карточки провайдера / нет apiKey / модель роли не добавлена — именованная
  остановка прогона до линз (роль, путь конфига zcode, недостающее) плюс
  страховка «ни один файл не прошёл ревью» вместо ложного «Находок нет».
- `docs/ops/install.md` называет машинные пререквизиты (git, node ≥ 18,
  python3, pytest), пререквизиту «модель ревьюера добавлена в zcode с
  карточкой провайдера» и границу ответственности: раннер вендорит payload в
  проекты, машинные инструменты и креды — уровень машины.
- `docs/reference/dependencies.md` — инвентаризация внешних зависимостей:
  апстрим ontoship-omp (gitmark.py, модель онтологии), neuraldeep (API,
  тарифы, потолки), zcode-хост (воркфлоу, хуки, MCP), маркетплейс-раннер,
  тулчейн; для каждой — текущий пин, канал обновления, владелец решения,
  деградация при мажоре, где ловится.
- Контур обновления апстрима: процедура синка `gitmark.py`/`ontology.md` из
  ontoship-omp (сегодня ручная, прецеденты queue-2) с критериями принятия
  решения.

## Scope

- `skills/ship/reviewer.workflow.ts` — fail-closed диагностика субстрата
  (карточка провайдера/ключ/модель в zcode) и профиль субстрата per-модель —
  карта `LENS_PROFILES` (тикет 04).
- `skills/ship/SKILL.md` — пересмотр команд шага 6 под зависимость.
- `skills/contour/SKILL.md` (новый) — поставляемые уроки механики
  zcode-workflow/хуков: потребитель не собирает грабли, найденные прогонами
  здесь (тикет 03).
- `docs/ops/install.md` — пререквизиты машины.
- `docs/reference/dependencies.md` — инвентаризация и контур.

Вне scope: смена субстрата confirm-рана (GLM-Flash через сабагентов хоста —
помещается, не трогаем), `code-review.workflow.ts` на coddy (отдельное
решение после 07, как и записано в тикете 07), механика самостоятельного
обновления coddy (его собственный канал, мы только фиксируем версию),
расширение обязанностей маркетплейс-раннера на машинные инструменты.

## Constraints

- Каждый тикет — полный луп `/ship` со своим релизным циклом.
- Креденшелы живут в zcode (`~/.zcode/v2/provider_config.json`): тесты и
  документация оперируют структурой конфига, значения ключей не читают и не
  печатают.
- Ответственность маркетплейса не расширяется: payload внутри проектов
  (пин/validate/update) — его уровень; машинные инструменты — уровень машины,
  документируются, раннером не устанавливаются.

## Context

Стена тарифа 2026-10-06: базовый вес запроса сабагента воркфлоу ~140k токенов
(контракт + схемы инструментов хоста) при потолке neuraldeep 138 336 — три
provider-stop за день, выживаемость первого запроса монетка. Решение
оператора: линзы гейта — прямые вызовы API neuraldeep из воркфлоу (промежуточная
попытка coddy вскрыла четыре своих отказа и закрыта); модель — безлимитный
тариф `neuraldeep/qwen3.6-unlim-xl`. План собран вручную из решений
оператора, без гриллинга (прецедент gate-followups). Файловых коллизий с
gate-followups-2 (05–07) и crossreview-adoption/03 нет: 01 правит
гейт-воркфлоу/install/гейт-диагностику, 02 — только новый док, 03 — новый
скилл и его маппинг/упоминание. Отгружены 01 (v0.5.31), 02 (без релиза —
доковый) и 03 (v0.5.32: skills/contour — 9 уроков механики zcode-workflow;
явный маппинг в deploy.json вместо предполагавшегося тикетом wildcard
`skills/*` — его в контракте раннера нет). 04 отгружен последним
(v0.5.33): обсуждение развёрнуто в кодовый тикет — карта профилей
LENS_PROFILES в воркфлоу, модель без профиля — именованный отказ,
«один файл на вызов» — инвариант; живая приёмка новой версии воркфлоу —
PASS. План закрыт целиком.
