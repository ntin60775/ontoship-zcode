# 04: Профиль субстрата линз per-модель (карта LENS_PROFILES)

**What to build:** субстрат линз гейта — прямые вызовы API провайдера из
воркфлоу (gate-followups-2/07; контур кредов закрыт тикетом 01, v0.5.31):
модель и креды приходят из карточки провайдера zcode в рантайме, а вся
подгонка под тариф жила разбросанными константами
`skills/ship/reviewer.workflow.ts` — границы диффа
`MAX_DIFF_LINES`/`MAX_FILES`/`MAX_FINDINGS`, порог инлайна
`LENS_INLINE_LINES`, `LENS_RETRIES`, `LENS_CALL_TIMEOUT_MS`,
`LENS_CONCURRENCY` — подобранными вручную под физику тарифа
`qwen3.6-unlim-xl` (вход ~138k, вывод 8000/ответ с thinking в том же
бюджете, dependencies.md) и при смене модели роли молча перестающими
подходить. Реализация: карта «модель → профиль» `LENS_PROFILES` в самом
воркфлоу (блок LENS PROFILE до констант); все семь констант читаются из
профиля выбранной модели; модель без профиля — именованный отказ гейта до
линз; «один файл на вызов» — инвариант гейта, в профиль не входит.

**Дизайн (решения оператора, 2026-10-08):**

- Формат карты: `LENS_PROFILES` — семь полей на модель (maxFindings,
  maxFiles, maxDiffLines, lensInlineLines, lensRetries, lensCallTimeoutMs,
  lensConcurrency); профиль живёт рядом с константами воркфлоу и
  резолвится до них (решение 1 от 2026-10-07: карта в репо).
- Граница карты и наблюдения: тарифные потолки в карточке провайдера zcode
  не живут (карточка несёт apiKey, baseUrl, список моделей и
  reasoning-уровни — факт 2026-10-08), probe-вызовы автоподстройку не
  кормят; источник фактов для профиля — датированные наблюдения
  docs/reference/dependencies.md, профиль обновляется руками.
- Фолбэк для модели без профиля — именованный отказ до линз: диагност
  называет модель, карту `LENS_PROFILES` для правки и место тарифных
  фактов; fail-closed, симметрично пробе субстрата 01. Вариант «требовать
  профиль в карточке zcode» умер с фактом «карточка потолков не несёт»,
  вариант «текущие константы молча» воспроизводил исходную болезнь тикета.
- Оверрайд оператора: карта в репо потребителя — правка профиля и есть
  оверрайд; /roles выбирает модель, не параметры; пререквизит прежний —
  модель добавлена в zcode, иначе check-режим 01 останавливает гейт иначе.
- reasoning у линз — high; автотюнинг reasoning отменён; reasoning не
  параметр вызова: тело запроса `{model, messages}`.
- «Один файл на вызов» — инвариант гейта при любой модели: топология линз
  и честный coverage завязаны на пару файл×линза, confirm-контракт ест
  per-file находки; окно вывода модели на инвариант не влияет.

**Живые факты, на которых стоит задача (2026-10-07/08):**

- reasoning не параметр вызова: тело запроса `{model, messages}`;
  unlim-xl reasoning'ит high (карточка ListModels: levels: high); low —
  осознанно отвергнут живой пробой (фабрикация находок на неполном
  материале). Поведенческий автотюнинг reasoning отменён оператором.
- Потолок вывода архитектурой не снимается: вариант «ответ в файл» (В1)
  отклонён при осознанном выборе субстрата 2026-10-07 (принят прямой API,
  живёт в `ND_CALL` reviewer.workflow.ts, пинен test_reviewer_substrate.py).
  Штатный контур — «один файл на вызов» + компакт-ретрай
  (`LENS_RETRIES=1`: не более 3 находок, evidence одной строкой) +
  принятая деградация на объёмных диффах (dependencies.md).
- Именованные отказы конверта (`classifyLensOutcome`,
  `totalSubstrateFailure`) пинены тестами: любое новое поведение
  автоподстройки обязано попасть в матрицу, а не только в прозу.

**Blocked by:** [01](01-zcode-credentials-contour.md) — archived

**Решения оператора (2026-10-07, в силе; пункт 2 скорректирован фактом
2026-10-08):**

1. Карта «модель → параметры субстрата» живёт в репо (профиль рядом с
   константами воркфлоу) — да.
2. Из карточки модели zcode профиль читает то, что там есть: модель,
   reasoning-уровни, capabilities. Тарифные потолки в карточку не входят —
   их место dependencies.md (датированные наблюдения, пин = место
   перепроверки). Пререквизит прежний: модель, выбираемая через roles,
   добавлена в zcode — check-режим 01 останавливает гейт иначе.
3. Оверрайд оператора третьим слоем roles — да.
4. reasoning у линз — high (на unlim-xl единственный в карточке);
   автотюнинг reasoning отменён.
