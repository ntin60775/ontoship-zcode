# 04: Автоподстройка конфигов линз под модель роли (обсуждение)

**What to build:** субстрат линз гейта (gate-followups-2/07) держит свои
настройки в трёх местах — `~/.coddy/config.yaml` (reasoning_default,
max_tokens), параметры воркфлоу (лимиты инлайна, размер evidence, finding-ов
на файл) и границы ретраев/таймаутов. Сегодня они подобраны вручную под
`qwen3.6-unlim-xl` и при смене модели роли молча перестают подходить.
Живой кейс 2026-10-07: reasoning high на unlim-xl сжигает бюджет вывода
тарифа в thinking ещё до ответа (пустые ходы, JSON оборван посередине);
после перехода на low — сфабрикованные находки на неполном материале.
Задача-обсуждение: спроектировать автоподстройку — при смене модели роли
(roles) параметры субстрата выставляются по карточке модели из zcode
(ListModels: уровни reasoning, тариф/потолки контекста и вывода, если
доступны) и по наблюдаемому поведению рана (empty-turn паттерн = thinking
съедает бюджет → низить reasoning; обрыв JSON на фиксированной позиции =
потолок вывода → резать evidence/файлы на вызов). Открытые вопросы для
обсуждения: где живёт карта «модель → параметры» (конфиг coddy против
блока в roles.md против данных ListModels на лету); что делать при
отсутствии данных о потолке вывода в карточке (probe-вызов при
первом прогоне?); не размывает ли автоподстройка ответственность /roles
(тикет 01).

**Blocked by:** [01](01-roles-manages-coddy.md) — руление конфигом coddy
должно устояться до его автоподстройки.

- [ ] дизайн-док: карта «модель → параметры субстрата», источник правды,
      механика смены модели роли без ручной подстройки
- [ ] живой кейс reasoning-пожора зафиксирован как тест-паттерн (empty-turn
      → диагностический abort с подсказкой низить reasoning)
- [ ] решение оператора по открытым вопросам, тикет закрывается либо
      разворачивается в кодовый
