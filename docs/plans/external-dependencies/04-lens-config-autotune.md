# 04: Автоподстройка конфигов линз под модель роли (обсуждение)

**What to build:** субстрат линз гейта (gate-followups-2/07) держит свои
настройки в трёх местах — `~/.coddy/config.yaml` (reasoning_default,
max_tokens), параметры воркфлоу (лимиты инлайна, размер evidence, finding-ов
на файл) и границы ретраев/таймаутов. Сегодня они подобраны вручную под
`qwen3.6-unlim-xl` и при смене модели роли молча перестают подходить.
Живой кейс 2026-10-07: reasoning high на unlim-xl сжигает бюджет вывода
тарифа в thinking ещё до ответа (пустые ходы, JSON оборван посередине);
после перехода на low — сфабрикованные находки на неполном материале.
Задача-обсуждение: спроектировать автоподстройку — при смене модели роли
(roles) параметры субстрата выставляются по карточке модели из zcode
(ListModels: уровни reasoning, тариф/потолки контекста и вывода, если
доступны) и по наблюдаемому поведению рана (empty-turn паттерн = thinking
съедает бюджет → низить reasoning; обрыв JSON на фиксированной позиции =
потолок вывода → резать evidence/файлы на вызов). Открытые вопросы для
обсуждения: где живёт карта «модель → параметры» (конфиг coddy против
блока в roles.md против данных ListModels на лету); что делать при
отсутствии данных о потолке вывода в карточке (probe-вызов при
первом прогоне?); не размывает ли автоподстройка ответственность /roles
(тикет 01).

**Blocked by:** [01](01-zcode-credentials-contour.md) — контур кредов на
zcode должен устояться до автоподстройки профиля.

**Решение оператора №5 (2026-10-07):** ключ и baseUrl — из карточки
провайдера zcode (`~/.zcode/v2/provider_config.json`); omp `models.yml` —
лишняя зависимость, не трогаем. Весь контур поставки провайдеров/моделей и
кредов замыкается на zcode; roles работает только с моделями, добавленными
в zcode.

**Решения оператора (2026-10-07, по четырём предложениям):**
1. Карта «модель → параметры субстрата» живёт в репо (профиль рядом с
   константами воркфлоу) — да.
2. Данные для профиля брать из карточки модели zcode — там всё есть:
   context window, max output tokens (у unlim-xl — 8000 за ответ),
   reasoning levels, capabilities. Пререквизит: любая модель, выбираемая
   через roles, должна быть сначала добавлена в zcode со своей карточкой.
3. Оверрайд оператора третьим слоем roles — да.
4. reasoning у линз — всегда high (запись в конфиге coddy одна): только
   high и есть в карточке, low — осознанное решение оператора, даёт
   неадекватные результаты (живая проба: фабрикация находок).
   Поведенческий автотюнинг reasoning отменяется.

**Снятие потолка вывода — архитектура «ответ в файл» (решение оператора):
линза пишет ответ по частям в файл (единственная разрешённая запись),
файл — результат её работы; воркфлоу читает файл после вызова, temp
чистится после прогона. Ходы модели могут уходить целиком в thinking —
ответ копится в файле и потолком 8000/ход не режется.**
