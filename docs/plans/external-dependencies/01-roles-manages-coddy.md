# 01: /roles рулит моделями coddy

**What to build:** субстрат гейта на coddy (gate-followups-2/07) делает
`~/.coddy/config.yaml` частью конфигурации гейта: модель ревьюера должна
существовать в его списке models, иначе линзы не стартуют. Сегодня это
рулится руками и нигде не сверяется. `/roles` становится единственной точкой
руления моделями гейта: resolve показывает модель ревьюера в coddy-форме
(`neuraldeep/<model>`) и сверяет её наличие в конфиге coddy — дрейф
именуется, а не молчит; set/unset правят список models текстуально (урок
пин-правок: без json.dump и переформатирования чужих комментариев),
провайдерные секции и ключи не трогаются вовсе. Гейт fail-closed по
субстрату: coddy не установлен / модель не сконфигурирована — остановка
прогона с диагностикой, называющей роль, путь конфига и недостающее.
Команды пересматриваются под зависимость: шаг 6 `/ship` берёт reviewerModel
из roles (уже так), `docs/ops/install.md` получает раздел машинных
пререквизитов (git, node, python3, pytest, coddy) с границей: раннер вендорит
payload, машинные инструменты — пререквизит машины.

**Blocked by:** None (can start immediately).

- [ ] `roles resolve` показывает модель ревьюера в coddy-форме и статус
      наличия в `~/.coddy/config.yaml`; дрейф именован
- [ ] `roles set/unset` правят список models конфига coddy текстуально;
      после правки `coddy -t` валиден; провайдерные секции не изменены
      (тест сравнивает их байт-в-байт)
- [ ] гейт останавливается с именованной диагностикой при: нет бинарника
      coddy; модель роли отсутствует в конфиге (живые пробы обеих веток)
- [ ] install.md: раздел машинных пререквизитов и граница ответственности
      раннера
- [ ] `gitmark lint --strict` + `pytest` зелёные
