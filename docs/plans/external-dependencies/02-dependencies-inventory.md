# 02: Инвентаризация внешних зависимостей

**What to build:** плагин живёт не в вакууме, но полный список внешних
зависимостей нигде не собран — каждая всплывает в момент, когда ломается
(стена тарифа 2026-10-06 — свежий пример: узнали о потолке в момент
provider-stop). `docs/reference/dependencies.md` — инвентаризация всех
внешних зависимостей двух классов: сторонние решения (neuraldeep API и
тарифы с потолками, coddy — бинарник/конфиг/канал обновления, zcode-хост с
его примитивами — воркфлоу, хуки, схемы инструментов сабагентов, MCP,
маркетплейс sot-zcode-marketplace с раннером, тулчейн — python3, node,
pytest, git, bash) и апстрим базового онтошипа — ontoship-omp (Ковальский,
github.com/vakovalskii/ontoship): общий движок `gitmark.py` и модель
онтологии вендорены сюда, синк сегодня ручной. Для каждой зависимости:
зачем нужна, где зафиксирована версия/пин, канал обновления, владелец
решения об обновлении, что ломается при мажоре, где это ловится (тест,
fail-closed диагностика, ручная проверка). Плюс два контура замены/синка:
провайдеры LLM (решение оператора 2026-10-07: механизм работает с любым
OpenAI-совместимым провайдером — карточка в zcode + args.provider/reviewer
Model + пул под тарифные лимиты; несовместимый протокол = одна ветка в
инлайн-скрипте ND_CALL; процедура замены — карточка → пробный вызов →
args → пул) и апстрим ontoship-omp: пошаговая процедура синка
`gitmark.py`/`ontology.md` с критериями принятия решения (когда тянем,
когда расходимся) — сегодня они живут только в прецедентах queue-2 и
живом цикле гейта 07.
