# Кап гейт-лупа /ship (gate-loop-cap)

## Goal

Гейт-луп шага 6 /ship получает записанный критерий окончания: кап 3
автоматических раунда, досрочный выход на чистом раунде, на исчерпании
капа — стоп-поинт с решением оператора; каждый раунд сверх капа
открывается только явным решением, по одному. Сегодня луп не записан
вовсе — исполнитель крутит review→confirm→fix без границы (живой кейс:
queue-3/02 остановлен ручным решением на r4).

## Done

Форма проб — grep -F без -i (урок fs03 r2: -i ломается на кириллице в
ru_RU.UTF-8); якоря правятся тем же фикс-коммитом при гейт-правках
формулировок (прецедент fs03 r1–r3).

1. Блок лупа в шаге 6 (после параграфа unconfirmed/unverified, перед
   шагом 7) записывает: раунд = review+confirm+адресация verified;
   чистый раунд = 0 verified и без unverified; якорь «кап 3 раунда до
   стоп-поинта».
2. Якорь бюджетной модели: «каждый раунд сверх капа — только явным
   решением оператора, по одному»; нечистый сверх-раунд — снова
   кап-стоп-поинт, чистый — обычный выход.
3. Якорь «перезапуск умершего или неполного рана новым раундом не
   считается» (model-death, coverage-fail).
4. unverified-карв-аут: якорь «unverified не делает раунд чистым» +
   ровно один чистый перезапуск confirm-рана вне счёта раундов (по
   образцу review-релонча), повтор — стоп с диагностикой.
5. У stop-before-commit записан второй триггер «исчерпание капа»:
   AskUserQuestion с тремя опциями — добить (ровно один раунд) /
   принять остатки / оформить хвосты ишью; отчёт несёт историю раундов
   (verified/unconfirmed/unverified на раунд, что закрыто, что
   осталось); шаг 6 и секция стоп-поинтов ссылаются друг на друга
   (условия — в шаге 6, механика стопа — в секции, один канон).
6. В блоке шага 6 записано: кап един для обоих контуров (лёгкий
   отличается только пропуском confirm при 0 находок).
7. Ранбук docs/ops/git-flow.md не тронут (делегирование «шаги и
   стоп-поинты лупа — в skills/ship/SKILL.md» живо).
8. Вендорная копия: после self-update релиза
   `diff skills/ship/SKILL.md .zcode/skills/ship/SKILL.md` пуст
   (git-отслеживаемые файлы); deploy-check exit=0.
9. Факт первого прогона под правилом записан в этом файле (какой
   прогон, каким раундом закрылся, дошёл ли до капа) — на шипе этого
   плана; после записи файл .zcode/ontoship/issues/04-gate-loop-cap.md
   удалён тем же раном. До шипа в 04 — строка «взято в план
   gate-loop-cap», ишью остаётся открытым (страховка между ранами).
10. Сьют и lint --strict зелёные; инвентарь реестра перегенерирован.
