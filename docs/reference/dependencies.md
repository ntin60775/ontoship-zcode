# Внешние зависимости — инвентаризация и контуры замены/синка

Плагин живёт не в вакууме: у каждой внешней зависимости свой конфиг, свой канал
обновления и своя точка отказа. До 2026-10 список нигде не собирался — зависимость
всплывала в момент поломки (стена тарифа 2026-10-06: о потолке узнали по
provider-stop'у). Здесь инвентаризация двух классов — сторонние решения и апстрим
базового онтошипа — и два контура: замена модели роли LLM и синк апстрима
(external-dependencies/02).

Правило: новая зависимость или вывод старой = правка этого дока в том же тикете,
что меняет контур. У каждой зависимости шесть полей: зачем нужна, где пин,
канал обновления, владелец решения, что ломается при мажоре, где ловится.

## Сторонние решения

### neuraldeep — карточка провайдера zcode; гейт с 2026-10-11 не вызывает

- **Зачем**: с 2026-10-11 — никак для гейта: прямой API-контур линз
  демонтирован (roles-fallback-substrate/03, «Субстрат линз» ниже), транспорт
  линз ревью — только субагенты хоста (раздел zcode-хост ниже). До того
  (2026-10-07 — 2026-10-11) — фолбэк-субстрат: при `substrate="direct"` гейт
  звал `chat/completions` напрямую из воркфлоу (gate-followups-2/07), дефолтом
  с 2026-10-09 были субагенты хоста на модели роли рана через `subagent_model`
  (2026-10-09 моделью линз была роль `confirmer`; с 2026-10-11,
  roles-fallback-substrate/02, review-ран идёт на роли `reviewer`, confirm —
  на `confirmer`). Карточка провайдера остаётся в zcode ради будущих
  не-субагентных применений (решение оператора 2026-10-09); моделей ролей это
  не касается — user-слой с 2026-10-11 на `GLM-5.3-Flash` (reviewer `$max`,
  challenger `$high`, [roles.md](roles.md)); до того обе роли сидели на
  `qwen3.6-unlim-xl` — модель списана 2026-10-09 (см. «Субстрат линз:
  решения 2026-10-09» ниже).
- **Пин**: версии нет — подписка. Карточка провайдера в zcode
  (`~/.zcode/v2/provider_config.json`, провайдер `neuraldeep-sub`: `access.apiKey`,
  `api.baseUrl`); ключи в репо не хранились и не печатались и в direct-ветке
  (external-dependencies/01). Факты тарифа `unlim-xl` (на 2026-10-08, для
  истории): потолок входа 138 336 токенов на запрос; вывод 8 000 токенов за
  ответ, thinking в том же бюджете; reasoning только `high`; `finish=length` —
  обрыв ответа. Сопоставимый факт по хост-субагентам (на 2026-10-08): базовый
  вес запроса субагента ~141k токенов (контракт воркфлоу + схемы всех
  инструментов и MCP); тарифный план zai несёт его целиком — раны
  dwfrun-0f9b01df (24+ сессий) и dwfrun-68730a08 прошли без единого отказа;
  тот же вес против потолка neuraldeep 138 336 давал три provider-stop'а за
  день (2026-10-06) — отсюда были и прямой фолбэк, и затем его списание.
- **Канал обновления**: подписка neuraldeep.ru (карточка). Для гейта канала
  нет — он neuraldeep не вызывает.
- **Владелец**: оператор (подписка и карточка).
- **Ломается при мажоре**: для гейта — ничего: прямого контура нет, любое его
  возвращение ловит absence-проба `tests/test_reviewer_substrate.py`. Для
  будущих не-субагентных применений карточки — не-OpenAI-совместимый протокол
  и урезание тарифа (provider-stop, `finish=length`). Наблюдение 2026-10-08
  (гейт crossreview-adoption/03): docs-линза на 203-строчном .md не влезла в
  вывод дважды подряд (основная попытка и компакт-ретрай direct-ветки),
  перезапуск рана прошёл чисто — недетерминизм thinking; класс деградации
  «выходной бюджет не вмещает ответ» остаётся и на субагентах — ContextLimit
  ловится в скрипте как именованный failed файла. Решение оператора
  2026-10-08: деградация принята, механика не меняется; шардирование входа
  против физики выходного бюджета не работает и ломает полноразмерный
  контекст docs-линзы. Протокол рана прежний: именованный провал файла — один
  чистый перезапуск review-рана, второй провал того же файла — стоп оператору
  с диагностикой (skills/ship/SKILL.md, шаг 6).
- **Где ловится**: absence-проба маркеров прямого контура в
  `reviewer.workflow.ts` (`tests/test_reviewer_substrate.py`); в живом
  субстрате — страховка `totalSubstrateFailure` («ни один файл не прошёл
  ревью» вместо ложного «Находок нет») и именованный failed файла при отказе
  вызова линзы.

### zcode-хост — примитивы, на которых стоит плагин

- **Зачем**: всё исполнение плагина: слэш-скиллы, воркфлоу (`CreateWorkflow`,
  `AmendWorkflow`, `ResumeWorkflowRun`), хуки (`SessionStart`, строгая JSON-схема
  `additionalContext`), субагенты с базой запроса ~141k токенов (контракт плюс
  схемы всех инструментов и MCP), слои ролей (default → user → project), карточки
  провайдеров.
- **Пин**: в репо пина нет — хост машинный, репо таргетит примитивы, не версию.
  Наблюдение на 2026-10-08: deb-пакет `zcode 3.14.4-7912` (`dpkg -s zcode`).
- **Канал обновления**: собственный канал хоста (deb), репо неподконтролен.
- **Владелец**: оператор машины.
- **Ломается при мажоре**: рост схем инструментов поднимает базу запроса
  сабагента — стена тарифа 2026-10-06 (три provider-stop'а за день) тогда
  лечилась уходом на прямой API (gate-followups-2/07); с 2026-10-09 дефолт
  снова субагенты (lens-substrate-flash: план zai несёт базовый вес ~141k —
  наблюдение в разделе neuraldeep выше), а с 2026-10-11 прямого фолбэка
  больше нет (демонтаж — «Субстрат линз» ниже): обратный дрейф тарифа zai
  лечится сменой модели роли на ту, чей план несёт вес субагента
  («Контур замены модели роли» ниже); смена контрактов хуков и воркфлоу
  (прецеденты: схема SessionStart, безусловное окно подтверждения воркфлоу).
- **Где ловится**: живые пробы при приёмке (гейт — прогон на реальном ране);
  поведенческие тесты пинят контракты (`tests/`); готчи документируются —
  [workflow-args.md](workflow-args.md), уроки механики — поставляемый скилл
  `skills/contour` (external-dependencies/03).

### coddy — выведен из контура (2026-10-07)

- **Зачем был**: промежуточный кандидат субстрата линз между «субагенты хоста»
  и «прямой API»: бинарник, конфиг `~/.coddy/config.yaml`, собственный канал
  обновления.
- **Вердикт**: вскрыл четыре собственных отказа (кап 30 ходов, смерть на капе без
  финального ответа и др.) — контур замкнут на zcode, решение оператора
  2026-10-07 (external-dependencies/01). В исходнике гейт-воркфлоу coddy-ссылок
  нет (с 2026-10-11 — как и всего прямого API-контура: absence-проба
  `tests/test_reviewer_substrate.py`); в комментариях истории субстрата coddy
  остаётся как отклонённый кандидат, кода он не касается.
- **Владелец**: вне плагина; канал обновления свой, плагину безразличен.
  Возвращение кандидатом — только через новый тикет.

### Тулчейн машины

- **Зачем**: исполнение движка, тестов и хуков: `git` (KB — md+git; git-операции
  движка), `python3` (движок — чистый stdlib), `pytest` (сьют плагина), `node` ≥ 18
  (поведенческие срезы workflow-логики в сьюте; 23+ снимает типы сам,
  22.6–22.x — через `--experimental-strip-types`), `bash` (хуки).
- **Пин**: [../ops/install.md](../ops/install.md), «Machine prerequisites»
  (external-dependencies/01); единственная названная версия — node ≥ 22.6.
- **Канал обновления**: системные пакеты машины; раннер ничего не ставит —
  граница ответственности зафиксирована там же.
- **Владелец**: оператор машины.
- **Ломается при мажоре**: node ниже 22.6 — поведенческий слой сьюта
  непрогоняем (нет ни снятия типов, ни `--experimental-strip-types`); без
  pytest непрогоняем сьют; без git разваливается сама модель KB.
- **Где ловится**: install.md как чек-лист; первые же красные — `lint`, `index`,
  `pytest`.

## Субстрат линз: решения 2026-10-09

Датированные записи, на которых держится демонтаж прямого API-контура линз
(план [roles-fallback-substrate](../plans/roles-fallback-substrate/README.md);
демонтаж кода — тикеты 03–04 плана, факт-слой — здесь):

- **Пол моделей** — постулат оператора (2026-10-09): рабочие модели хоста —
  окно входа ≥262k токенов, вывод ≥131k. Постулат, не замер: на 2026-10-11 ни
  один потолок карточек провайдеров его не опроверг — базовый вес субагента
  ~141k (наблюдение в разделе neuraldeep выше) и объёмные линз-ответы
  влезают целиком, обходной прямой вызов не нужен.
- **Транспорт линз — только штатные субагенты** (решение оператора,
  2026-10-09): ветка `substrate="direct"` (ND CALL, `LENS_PROFILES`, пул,
  таймауты, JSON-ремонт, ручной redact) демонтируется до нуля клиентов;
  `classifyLensOutcome` адаптируется на исходы субагентов. Узость ростка
  линз — принцип, а не компенсация слабой модели: ростер шести осей и
  инвариант файл×линза не меняются (агрегация ростера отвергнута).
  «Нерезолвящееся — не деградация»: модель, которой нет на хосте (ListModels),
  остаётся fail-closed стопом до запуска — фолбэк ошибки конфигурации не
  маскирует.
- **Демонтаж исполнен** (2026-10-11, тикет 03): ветка прямого вызова снесена
  целиком — инлайн-вызов, тарифная карта, пул воркеров, таймауты,
  компакт-ретрай, JSON-ремонт, проба субстрата; args
  `substrate`/`reviewerModel`/`provider` исчезли из декларации воркфлоу
  (остались `ticket`/`base`/`root`); `classifyLensOutcome` переведён на исходы
  субагентов — ответ типизирован хостом, исхода два: ответ или исключение
  вызова (именуемое в failed файла, через redact). absence-пин маркеров
  прямого контура — `tests/test_reviewer_substrate.py` (absence-проба с живой
  мутационной проверкой детектора); приёмка — полный гейт живым прогоном на
  субагентах. Хвосты пула (идентичность задач драйвера, ветка N<cap) закрыты
  самим демонтажем — пинов не требуют.
- **qwen3.6-unlim-xl списан** (решение оператора, 2026-10-09): потолок входа
  тарифа 138 336 ниже базового веса субагента ~141k — субагентом модель не
  работала никогда, прямой вызов остаётся без ветки. Полезный опыт: паттерн
  прямого API из карточки провайдера zcode (инлайн-вызов `node -e`, креды
  только из карточки), факт «тариф ≠ карточка» (model-id резолвится, тариф
  не привязан), finish=length-протокол coverage (обрыв → компакт-ретрай →
  перезапуск рана). Финансовый вывод: вложение не окупилось; карточка
  neuraldeep-sub остаётся в zcode ради будущих не-субагентных применений.

## Контур замены модели роли LLM

Предпосылка (решение оператора 2026-10-07, переписано 2026-10-11 тикетом 03
плана roles-fallback-substrate): слой сущностей — zcode, движок не заводит
свой реестр моделей. С 2026-10-11 линзы ходят только субагентами хоста, поэтому
«смена провайдера» для гейта — это смена модели роли: карточка в zcode плюс
`/roles set`. Прямого API-пути больше нет («Субстрат линз» выше). С октября
2026 фасад воркфлоу даёт и **пер-агентные модели** — `model` в persona
субагента (живой зонд dwfrun-e8132143: два субагента одного рана без раннего
`subagent_model` ответили на разных моделях); компиляторский предел — `model`
persona обязан быть известен до старта рана, строка из args отвергается,
поэтому роль входит в ран ровно двумя мостами (полный контракт —
[roles.md](roles.md), «Два моста»).

1. **Модель в карточке zcode.** В `~/.zcode/v2/provider_config.json`: модель
   добавлена провайдеру — в `personalModelIds` или в
   `providerModelRules`/`manualProviderModelRules` этого провайдера; тогда она
   видна в ListModels. Ключ не печатается нигде.
2. **Назначение роли.** `/roles set <роль> <модель>$<уровень>` в user-слой
   ([roles.md](roles.md)). Модель, которой нет в ListModels, — fail-closed
   стоп до запуска (шаг 6 [../../skills/ship/SKILL.md](../../skills/ship/SKILL.md));
   фолбэк ошибки конфигурации не маскирует («Нерезолвящееся — не деградация»).
3. **Мост в ран.** Аргументов провайдера и модели у воркфлоу нет. Мост №1 —
   одноролевой ран: модель задаёт CreateWorkflow через `subagent_model`
   (гейт: review — `reviewer`, confirm — `confirmer`). Мост №2 —
   многоролевой движок-шаблон: `{{ROLE_MODEL:<роль>}}` в шаблоне, запускающий
   скилл после resolve+ListModels инстанцирует литералы в уникальный черновик
   с дифф-префлайтом (первый потребитель — онто-док, roles-per-agent/02).
4. **Приёмка замены.** Прогон гейта на малом диффе (сырые находки доезжают до
   confirm-рана) плюс сьют пинов `tests/test_reviewer_substrate.py`;
   для моста №2 пины матрицы запуска и дифф-префлайта появляются тикетом
   roles-per-agent/02 — до него `tests/test_run_model_column.py` пинит
   только гейт моста №1.

Граничные случаи:

- **Не-OpenAI-совместимый протокол** — вопрос карточки zcode (хост ходит в
  провайдера по openai-chat-completions), воркфлоу протокола не знает.
  Адаптер под чужой протокол извлекается по второму живому провайдеру, не
  заранее (решение оператора 2026-10-07); до второго живого провайдера
  несовместимый не подключается.
- **Отказ субстрата**: контур моделей/уровней закрывает скилл до рана (шаг 6,
  fail-closed); страховка `totalSubstrateFailure` не даёт ложного «Находок
  нет», отказ вызова линзы — именованный failed файла (external-dependencies/01).
- **Тарифный дрейф хоста** (окно или вывод сузились): лечится сменой модели
  роли на ту, чей план несёт базовый вес субагента ~141k (постулат поля
  моделей — «Субстрат линз» выше), не возвратом прямого API — его больше нет.

## Контур синка апстрима (gitmark.py, онтология)

1. **Мотив.** Конкретный багфикс или фича апстрима; плановая сверка — не чаще
   раза в квартал. Без мотива синк не проводить: расходимся.
2. **Дифф.** Клон апстрима (github.com/vakovalskii/ontoship), diff
   `.omp/skills/kb-search/gitmark.py` против `skills/kb-search/gitmark.py`;
   отдельно — изменения модели онтологии против docs/ontology.md.
3. **Классификация** каждого изменения:
   - багфиксы движка (FTS5-поиск, lint, inventory, map) — тянем;
   - фичи, не привязанные к omp-слою, — тянем;
   - omp-специфика (пути `.omp/`, omp-команды, интеграции omp-хоста) — не тянем,
     фиксируем расхождение в хедере.
4. **Перенос минимальным диффом** (правило хедера); хедер обновить —
   апстрим-версия и дата синка; локальный `VERSION` бампить по смыслу.
5. **Проверка синка**: полный сьют `python3 -m pytest tests/ -q`; матрица
   дифф-парсеров `tests/diff_map.mjs` (через `tests/test_diff_map.py`);
   `gitmark lint --strict`; rebuild индекса; `scripts/deploy-check.sh`.
6. **Отгрузка.** Менялся вендоренный payload (`skills/` мапится deploy.json) —
   полный релизный цикл: бамп, тег, пин, self-update ([../ops/git-flow.md](../ops/git-flow.md));
   правки только в `docs/` едут без релиза — `docs/` раннер не вендорит.

**Критерий «расходимся»**: апстрим ушёл в omp-специфику так, что перенос дороже
собственного развития, — фиксируем форк в хедере (дата, причина, апстрим-версия)
и закрываем тикет синка без переноса. Возвращаемся по конкретному багфиксу.

Прецеденты: первичный вендоринг при создании репо (0.4.8 → локальная 0.1.0);
переезд потребителей с omp — [../ops/migration-omp-to-zcode.md](../ops/migration-omp-to-zcode.md)
(аудит keep/drop/replace, queue-2/19).
