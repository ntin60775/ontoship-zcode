# Git-флоу — соло-режим без MR

Согласовано с оператором 2026-10-06 (после отгрузки v0.5.23). Это формальный
флоу, а не описание прецедентов: агент ожидает каждый его пункт, не
переоткрывает и не декларирует отступлением.

## Режим

- Один коммиттер; механизма MR нет — **все мержи локальные `--no-ff`** с
  сообщением `merge: <что> — <контекст>`.
- Удалённый репозиторий есть не у каждого контура: **пуш — «если есть куда»**.
  Отсутствие remote — штатный режим, не отступление; в шиппинг-ноутах не
  декларируется.
- Оператор смотрит диффы в стоп-поинтах, **когда считает нужным**; глубина
  просмотра — его выбор, остановка перед коммитом обязательна. Его `continue` —
  сигнал коммитить и пушить. Дифф ему в отчёты и окна подтверждений не
  вставляется: стоп-поинт и подтверждение сообщают фактами (хэши, файлы,
  счётчики, вердикты гейта); дифф показывается только по явной просьбе
  («покажи дифф»).

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | истина, всегда зелёная; вендорится только из тега |
| `dev` | интеграционная, локальная; **доставка клиенту прямо из dev — штатный процесс** (раздел ниже) |
| `ship/<slug>-<nn>` | тикетная; всегда в выделенном worktree `../<repo>-ship-<nn>` |

Работа по `main` в основном чекауте запрещена: кодовые изменения живут только
в тикетных ветках.

## Цикл кодового тикета

Для всего, что вендорится (скиллы, хуки, движок, скрипты) — полный луп
`/ship`; шаги и стоп-поинты лупа — в [../../skills/ship/SKILL.md](../../skills/ship/SKILL.md).
Git-часть:

1. Worktree `../<repo>-ship-<nn>`, ветка `ship/<slug>-<nn>` от `main`.
2. Реализация; фича-коммит. Аменд до пуша свободен, после пуша — только новые
   коммиты.
3. Гейт по диффу ветки от merge-base.
4. Стоп-поинт: отчёт фактами (хэши, файлы, счётчики, вердикт гейта) →
   `continue`; дифф не вставляется — по явной просьбе оператора.
5. Мерж `--no-ff` в `dev`, полный suite на `dev`, `push origin dev` (если
   remote есть).
6. Одно окно подтверждения, два вопроса: мерж в `main` + деплой.
7. Мерж `--no-ff` в `main` (`merge: dev — <тикет> отгружен …`), релиз — раздел
   ниже.
8. Деплой-хвост, архивация тикета, push `main`.
9. Снятие worktree, удаление тикетной ветки.

## Доковые и опс-коммиты

Планы, архивация тикетов, KB, каталог маркетплейса — **прямо в `main`**, минуя
`dev` и релизный цикл; suite + `lint --strict` перед пушем.

## Релиз из `main`

1. Bump `version` в `package.json` → коммит `chore(release)` → **лёгкий** тег
   `vN.N.N`.
2. `git push origin main`, затем **явно** `git push origin vN.N.N`.
   `--follow-tags` лёгкие теги не толкает (урок v0.5.23 — на него не
   полагаться).
3. Деплой-хвост: пин в маркетплейсе (`ref` и `version` записи согласованы —
   валидатор сверяет) → `validate --fetch` → self-update в проектах-потребителях
   → inventory-синк → архивация тикета → push `main`.

Каталог маркетплейса может обновляться между чтениями — перед правкой пина
перечитать `git status` и значения записи. Операции раннера —
[install.md](install.md).

## Доставка из `dev` (штатная)

Триггер: оператор решает доставить клиенту состояние `dev` до очередного
релиза из `main` (фикс нужен сейчас, полный релизный цикл — нет). Процесс:

1. `dev` зелёный на доставляемом коммите: полный suite + `lint --strict`.
2. **Лёгкий тег на точный коммит `dev`: `vB.B.B-dev.N`** — база `B.B.B` =
   последний выпущенный релиз (`v0.5.23-dev.1` — первая доставка поверх
   v0.5.23), `N` наращивается в рамках базы.
3. Явный пуш тега.
4. Пин каталога — **на dev-тег**, не на ветку и не на хэш: тег воспроизводим,
   ветка плывёт. Не-semver ref проходит `validate` без сверки `version`
   (сверка пин-тега срабатывает только на `^vN.N.N$`) — осознанное послабление.
5. `metadata.version` каталога поднять, `validate --fetch`, push каталога.
6. `update ontoship <клиентский проект>` тем же раннером.

Возврат: следующий релиз из `main` возвращает пин на семверный тег; dev-теги
не «повышаются» в `main` и не удаляются. Факт доставки из dev и причина
фиксируются в отчёте прогона или слепке.

## Подтверждения

- Дефолтный стоп-поинт (когда Constraints плана не называют иного): после
  гейта — отчёт фактами, ждать `continue`; дифф не вставляется (раздел
  «Режим»).
- Мерж в `main` и деплой — два вопроса одним окном; ответ оператора «continue
  и деплой» одним сообщением закрывает оба.

## Отступления-константы

Не декларируются как отступления, в шиппинг-ноутах — одной ссылкой сюда:

- **MR нет** — локальный `--no-ff` мерж в `dev` вместо MR.
- **Отдельного прод-контура нет** — шаг 8 лупа это полный suite +
  `deploy-check`; контур — сам проект с вендором.
- **Remote может отсутствовать** — пуш пропускается молча.
